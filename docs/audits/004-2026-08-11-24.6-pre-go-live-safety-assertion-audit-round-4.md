## Findings

### F20 · `16.4`'s fail-visible coverage-degrade signal is discarded one hop past where it's minted — `ACC-1` → `### 24.24`

**Source:** ACC-1, tracing `16.4`'s Done-when claim hop-by-hop rather than trusting the tick. **Severity:** medium (guarantee holds; detection is lost — Drive records still commit correctly, but a partial sync page becomes operator-invisible). **Rule:** §8/§16 observability.

`packages/integrations/src/connectors/gateway.ts` mints a fail-visible `GatewayHealthSignal` correctly on the `"advanced"` branch when `incompleteSearch=true`. `projectSyncResult` (`packages/workflows/src/activities/connectorPoll.ts:61-80`) then does `if (result.status === "advanced") { return base; }` — and `base` carries no `healthSignal`/`healthReason` field; that field is attached only in the `else` (held/degraded) branch. The signal is discarded unconditionally on the one branch it was built for. `connectorSyncHealth.ts:451-461` mirrors the split, so the health sink is never reached for this case.

Two things elevate this beyond an ordinary miss: (1) the drop was introduced by the **same task** (`16.4`, `07e27aea`) whose own Done-when claims the opposite — never true, not a regression; (2) `connector-sync-health.test.ts:376-387`'s unit test for `projectSyncResult` constructs an `"advanced"` input **without** a `healthSignal` and asserts `healthReason` is `undefined` — it never exercises the scenario the task shipped to cover. The suite pins the branch beside the defect without ever entering it.

Filed as `### 24.24`, dormant today (§ARM-23 unbound); arming Phase 23 will not fix it — the drop is structural, independent of arming state.

### Method finding, not a code finding: `codegraph_callers` under-reports in this codebase's dominant idiom

While re-deriving the above, ACC-1 established that `codegraph_callers` **misses real call sites that live in object-literal property values or factory closures** — the dominant construction idiom in this codebase. This is recorded as an audit-instrument finding (parallel to round 1's "iterations-to-dry measures search-key saturation, not surface coverage" self-correction): **an under-reported caller would have turned "detection is lost" into a FALSE finding, blocking arming on a defect that does not exist.** The inverse-error framing matters — this round corrected far more over-claims than false doubts, and this is the one instrument gap that could have gone the other way. No task filed; recorded as a standing method note for any future zero-caller claim in this codebase — verify by grep-and-classify, not `codegraph_callers` alone.
