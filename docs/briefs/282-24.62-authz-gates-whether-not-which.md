## Feature

⛔⛔ **THIS IS A WORKSPACE-ISOLATION QUESTION — SAFETY RULE 4 — NOT AN AUDIT ONE. Know that before you start;
it is scoped this way from the first line deliberately, so it is not discovered mid-slice.**

body and reach the Copilot surface with B.** Establish whether anything, at any layer, actually scopes that.

a fix, and not a reassurance.**

## The question to answer

**Does anything, at ANY layer, bind the request's `workspaceId` to the authenticated principal?**

If **yes** — cite it at `file:symbol` and show what it rejects.
If **no** — then an authenticated principal can name any registry-valid workspace on the Copilot surface, which
is **a cross-workspace read that does not traverse the GCL Visibility Gate**, and safety rule 4 says the gate is
*the single cross-workspace read path*.

product, so *"the only caller is the owner, who owns every workspace"* **may well be the answer** — ⛔ **but that
is a THREAT-MODEL RULING, not a code fact, and it belongs to the owner via the lead.** ⭐ **Establish the code
behaviour and PRESENT it; do not resolve it by reasoning about the deployment shape.** *(If you find yourself
writing "but in practice…", stop — that sentence is the escalation, not the conclusion.)*
