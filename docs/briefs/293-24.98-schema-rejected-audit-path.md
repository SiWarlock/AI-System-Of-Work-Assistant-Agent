## ⛔⛔ THE BINDING CONSTRAINT — THE OBVIOUS IMPLEMENTATION IS THE DANGEROUS ONE. THIS IS THE SLICE.

The mechanism, measured at HEAD (`visibility-gate.ts` clean — `git diff HEAD --stat` empty):

1. `admitProjection`'s ajv/Zod stage runs **FIRST** and fail-closed, so a non-conforming **STORED** row is `schema_rejected` **before** the visibility stage ever runs.
2. `auditOf` (`visibility-gate.ts:79-83`) returns **`undefined`** for `schema_rejected` and `raw_content_present`.
3. `persistDenialAudit` (`projection.ts:80`) opens with `if (audit === undefined || auditPersist === undefined) return;`

⇒ **the refusal produces NO audit record.** Not a leak — the row *is* refused — but the refusal vanishes.

### ⛔ The trap, and it is a rule-7 trap

The obvious fix is *"thread the existing `issues` into an `AuditSignal`."* ⛔ **Do not reach for it before answering Q1.**

`GateIssue` (`visibility-gate.ts:29-32`) is `{ path, message }` and its docblock claims **"redaction-safe: path + message only."** ⚠ **That is an assertion about `path`, and `message` is not `path`.** `message` is **Zod-generated** (`visibility-gate.ts:145-148`, `i.message`), and:

- `GclProjectionSchema.visibilityLevel` binds `VisibilityLevelSchema` = **`z.enum(VisibilityLevel)`** (`packages/contracts/src/models/shared-enums.ts:18`) — measured.
- ⛔ **Zod's `invalid_enum_value` message embeds the RECEIVED VALUE** (`Invalid enum value. Expected 'a' | 'b', received '<the row's value>'`).

⇒ ⭐⭐ ***THREADING `issues` INTO AN AUDIT SIGNAL WOULD NEWLY ROUTE ROW-DERIVED CONTENT ONTO A RULE-7 SURFACE — for exactly the malformed rows this task exists to record.*** **The docblock's "redaction-safe" is an overclaim of `L82`/`L151`'s shape: a comment asserting a property nothing enforces.**

⛔ **AND THE FAILURE MODE IS THE ONE THAT LOOKS LIKE SUCCESS:** if the signal carries row-derived content, `isRedactionSafe` (`projection.ts:102`) **refuses** it — so the audit record is *still* not written, now with a refusal notice instead. ⇒ ***the gap reproduces for precisely the credential-shaped rows that motivated the task, while the suite goes green.*** That is `### 24.84`'s own decisive framing recurring one surface over: **a green count that IS the loss.**

⭐ **THE POSTURE THIS SLICE WANTS: the `schema_rejected` signal must be redaction-safe BY CONSTRUCTION, not by luck** — assembled from **non-row-derived** material (the `code`, the `stage`, issue **`path`s**, a **count**), never from `message`. `L73`'s inversion again: make the unsafe content **unrepresentable**, don't **detect** it.
