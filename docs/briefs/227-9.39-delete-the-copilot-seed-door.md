## Why this slice exists (read before Step 0)

9.25 shipped a 4-test scanner that goes RED if anyone passes `turns=` at a render site. It took **three adversarial reviewer rounds**, each closing a **demonstrated** — not theoretical — evasion: a regex scanner fell to a JSX spread; rewritten on the TypeScript compiler API it still matched the bare tag name, so an aliased import / namespace tag / `React.createElement` evaded it; with tag names resolved against imports, the reviewer found barrel re-export indirection. It was stopped at three rounds **by ruling**, with two residuals **named rather than closed**.

The durable reading 9.25 banked: ***"no production consumer" is a negative claim over an UNBOUNDED construction space, so a scanner over it is a DETECTOR, not a gate*** — and *"if this ever must be airtight, the structural answer is: DELETE the seed door and construct turns another way in tests."*

⇒ This slice does that. **Deleting the prop converts an open-space detector into a closed-space gate.** With no `turns` member on `CopilotProps`, there is nothing to police and both named residuals become *unreachable* rather than *accepted*.

⛔ **What this slice does NOT do, stated so it cannot be over-claimed in the commit message.** It does **not** solve disclosure-on-rehydrate. 9.25 established the fail-open-by-omission case is **unreachable today** — a different claim from *handled*. This removes the **construction route**; it does not create derived disclosure state. **A future restore path still owes 9.25's precondition in full — that obligation MOVES to the restore producer, it does not discharge.** Do not write "disclosure-on-rehydrate is solved" or "9.25 is closed" anywhere.

## RED test outline (Step 2)

⚠ This is a **deletion** slice, so RED is unusual: the honest failing test asserts the *absence* of the seam. Do not fake a RED by breaking something first.

1. **`turns prop is not part of CopilotProps`** — a compile-level assertion that passing `turns` to `<Copilot>` does not type-check.
   - Asserts: a `@ts-expect-error`-guarded `<Copilot turns={[]} … />` — RED today (the prop exists, so `@ts-expect-error` is unused and `tsc` errors on the unused directive), GREEN after deletion.
   - Why: L103 — this is the closed-space gate that replaces 9.25's open-space scanner. It is checked by `tsc --noEmit`, which is this repo's actual `lint`/typecheck gate, so it cannot silently stop running.
2. **`turn state starts empty with no seed`** — mounting `<Copilot>` renders zero turns.
   - Asserts: no `CopilotTurnView` is rendered at mount.
   - Why: pins that the initialiser no longer has a seed branch.
3. **`live-ask path still admits through door 1`** — driving a successful ask produces an admitted turn.
   - Asserts: `admitReply` still gates the live answer; a fabricated `egressProcessor` is still rejected to `ASK_FAILED`.
   - Why: §5 / 9.26 — the re-gate must survive door 2's removal. **This is the regression that would matter most.**
4. **`failed ask still renders ASK_FAILED`** — 9.24's guarantee unchanged.
   - Asserts: the explicit `ASK_FAILED` turn, not a silent render.
   - Why: 9.24 — the guarantee that a missing signal cannot produce a plausible-looking answer.
