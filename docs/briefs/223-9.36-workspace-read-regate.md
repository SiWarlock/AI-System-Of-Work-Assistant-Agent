# /tdd brief — workspace_read_regate_at_the_repository_boundary

## Feature
Re-gate the stored `Workspace` aggregate **at the `packages/db` repository read boundary** — replacing the unchecked `row as Workspace` casts with a parse that fails closed on a referentially-inconsistent row, via a **distinguishable** typed error, on **both dialects**.

⇒ **Every surface this slice touches is an AMPLIFIER of a pre-existing out-of-band corruption, never an originator.** Origination stays sqlite-CLI-edit / restore-from-stale-snapshot only — **9.29's recorded accepted residual**.

⛔ **Do NOT let this become "a foreign `workspaceId` is undetected."** That is the quotable version and it is **false**. The honest one-liner is: *a missing guard whose absence makes out-of-band corruption undetectable, on fields that have consumers willing to use them as identity.*

## ⛔ AMENDED 2026-07-29 AFTER DISPATCH — READ THIS BEFORE THE ENUMERATION

**Counting cast sites is the wrong completeness metric, and a fix that only removes the casts is a NO-OP.**

`packages/db/src/schema/workspace-config.ts` types **every** column with `$type<Workspace[...]>()` — including both nested aggregates: `egressPolicy: text({mode:"json"}).$type<Workspace["egressPolicy"]>()` and the same for `providerMatrix`. ⇒ **Drizzle's inferred select row is ALREADY structurally `Workspace`.** The six `as Workspace` casts are therefore **decorative, not causal**: delete them and the code still compiles and still admits an unvalidated row.

⇒ **The actual defect is a compile-time assertion about runtime-untrusted bytes.** `mode: "json"` runs `JSON.parse` and the result is *asserted* to be an `EgressPolicy` with **zero runtime validation**. Nothing about the stored blob has ever been checked at read time.

⇒ **THE COMPLETENESS CRITERION CHANGES.** Not *"all six cast sites parse"* but: **no read path out of `workspaceConfig` can return an unvalidated aggregate — including a reader added tomorrow that contains no cast at all.** A new `getByType()` written next month inherits the false type for free and needs no cast to do it. Pin the **property**, not the six constructions (contracts **L70**: pins written against the construction you happened to use get bypassed by a different construction).

⚠ **This also retires my own "six sites" framing as the measure of done.** The six are still the places to *change*; they are not the definition of *complete*. Recording the correction rather than quietly reframing it — the enumeration was accurate and measured the wrong thing.

## The enumeration — SIX cast sites, three per dialect

⛔ **SCOPE OF THIS ENUMERATION, stated with the count (contracts L100):** complete for the pattern **`as Workspace`** within **`packages/db/src`**. Additionally checked and **negative**: helper-shaped converters (`rowTo*` / `toWorkspace` / `asWorkspace`) — none exist for `Workspace`; **`satisfies Workspace`** — zero occurrences in production code; `as Workspace` **outside** `packages/db/src` — four production hits, **all `as Workspace["id"]`** (a string→branded-id cast at a call site, not a row→aggregate cast). ⚠ **And the residual the scope statement exposes: because of `$type<>()` above, a site needs NO cast at all to admit an unvalidated row — so no cast-shaped search, however wide, can establish completeness here.** That is why the criterion above is a property, not a count.

| # | Site | Method | Cast |
|---|---|---|---|
| 1 | `packages/db/src/adapters/sqlite/index.ts:362` | `get` | `row as Workspace` |
| 2 | `sqlite/index.ts:364` | `list` | `as Workspace[]` |
| 3 | **`sqlite/index.ts:412`** | **`updateProvisioningFields`'s `.returning()` row** | `updated as Workspace` |
| 4 | `packages/db/src/adapters/postgres/index.ts:383` | `get` | `row as Workspace` |
| 5 | `postgres/index.ts:385` | `list` | `as Workspace[]` |
| 6 | **`postgres/index.ts:430`** | **the same return** | `row as Workspace` |

⛔ Sites **3** and **6** are the ones an earlier four-site enumeration missed: the *narrowed write* method hands back the **whole post-write row**, including the posture columns it did not write. `insertIfAbsent` is clean (returns a boolean, no cast).

⭐ **AND THE IRONY IS THE FINDING, so do not skim it.** `updateProvisioningFields` is the method praised throughout task 9.30 and in this brief's own threat-model table as *"guard by construction"* — the narrowing that made a posture write **untypeable**. **It hands back the whole post-write row, so the RETURN re-introduces the very unvalidated read the narrowing was celebrated for eliminating.** ⇒ **A narrowed WRITER is not a narrowed READER, and nothing about the narrowing announces that.** The mechanism cited as closing the hole is itself one of the six sites — which is why the threat-model table above says the narrowed write cannot *originate* a foreign id (true, it writes no such column) while this section says its return can *serve* one (also true). Both hold; they are different directions through the same method.

## Acceptance criteria (what "done" means)
- [ ] A `Workspace` row failing the referential pin is **rejected on read** at the repository boundary, on **both** dialects — not served, not normalized. **Fail closed, never rewrite**: coercing a foreign `workspaceId` to the expected one would graft another workspace's allowlist + ack onto this workspace stamped as if it belonged (WS-8-adjacent, and legitimate-looking to every later reader).
- [ ] The rejection is a **distinguishable** typed error — separable from a store fault **and** from `not_found`. A caller can tell "this row is referentially inconsistent" from "the DB is unavailable."
- [ ] **No read path out of `workspaceConfig` returns an unvalidated aggregate — pinned as a PROPERTY, in a way that also catches a future reader containing no cast.** (See the amendment above: the six casts are decorative; `$type<>()` on the schema is what makes an unvalidated row assignable, so a cast-count criterion is satisfiable while the defect remains.) The six known sites are the places to change; the property is the definition of done.
- [ ] A stated subset is acceptable **only** if each unparsed path is named in `IMPLEMENTATION_PLAN.md` task 9.36 and justified. A silent partial is the failure mode here.
- [ ] `storeBackedWorkspacePosture.ts:39-40` no longer serves a corrupt policy: today it compares `String(ws.id) !== workspaceId` and returns `egress: ws.egressPolicy` with the nested id **never checked**.
- [ ] `packages/policy/src/workspace-policy.ts:7-10,:36` is **either true or amended in this same slice.** Leaving it asserting an unprovided guarantee is the defect this slice exists to close.
- [ ] Any raw/unparsed read escape hatch is **singular, named, and pinned as singular** — a test fails if a second caller appears. An unpinned escape hatch becomes the new unchecked cast.
- [ ] Dual-dialect coverage in `packages/db/test/contract/repository-contract.test.ts` — the one suite **both** adapters must pass (§4).
- [ ] The corrupt-row fixture is built by **cast**, not by the schema (the schema correctly refuses to construct it) — mirroring `apps/worker/test/composition/provision-preserves-egress-posture.test.ts:245-249`.
- [ ] `/preflight` clean. ⛔ Report it as **"typecheck + tests clean; no lint coverage exists"** — `pnpm lint` IS `tsc --noEmit`; ESLint is absent and unconfigured. Never write "lint clean."

## RED test outline (Step 2)
In `packages/db/test/contract/repository-contract.test.ts` (runs on **both** dialects):

1. **`a_referentially_inconsistent_row_is_rejected_on_get`** — Asserts: a row whose `egressPolicy.workspaceId` ≠ `id` (inserted by cast/raw write) makes `get` resolve a typed err with the referential-inconsistency code — **not** `ok`, **not** `store_fault`, **not** `not_found`. Why: §4 read contract + L76.
2. **`the_inconsistency_error_is_distinguishable_from_a_store_fault`** — Asserts: the corrupt-row code `!==` the code produced by an unavailable/failed read. 3. **`a_consistent_row_still_round_trips`** — Asserts: the ordinary valid workspace reads back byte-identical. **The non-vacuity control** — without it, a constant-deny read passes tests 1 and 2 (contracts L80: *if I replaced the gate with a constant DENY, would anything go red?*).
4. **`providerMatrix_inconsistency_is_caught_too_not_just_egressPolicy`** — Asserts: a row foreign **only** in `providerMatrix.workspaceId` is rejected. Why: contracts **L72** — a guard applied to one field of an aggregate is a silent fail-open for its siblings, and `buildActivities.ts:858-861` consumes exactly this field.
5. **`list_rejects_or_reports_an_inconsistent_row`** — Asserts: `list` does not silently return a corrupt row typed as valid. Why: sites 2/5; a per-`get` fix that leaves `list` casting closes three of six.
6. **`updateProvisioningFields_return_is_gated_too`** — Asserts: with a corrupt row stored, the narrowed update's **returned** aggregate does not arrive cast-but-unvalidated. Why: sites 3/6 — the write method hands back posture columns it never wrote.
7. **`the_gate_does_not_normalize`** — Asserts: after a rejected read the stored row is **unchanged** — no coercion, no repair-write. Why: fail closed, never normalize (L76).

In `apps/worker/test/composition/` (consumer-side, fail-closed direction):

8. **`posture_resolver_fails_closed_on_an_inconsistent_row`** — Asserts: `storeBackedWorkspacePosture.resolve` returns its fail-closed err rather than a posture carrying a foreign policy. Why: rules 4 + 5 — the §5 veto's input.

## Things to flag at Step 2.5
1. **Where does the parse live — in each adapter, or in one shared helper both adapters call?** My default vote: **one shared helper**, called from all six sites. Two independent parse implementations that happen to agree read exactly like one shared implementation until one drifts — and that duplication is itself the drift risk contracts **L75** names.
1b. ⛔ **RULED BY THE LEAD 2026-07-29 — the DIRECTION is settled, the syntax is yours.** **Type-level unrepresentability is the COMPLETENESS MECHANISM. A census pin is defense-in-depth BELT, never the mechanism.** How to express that in drizzle/TS is your call at Step 2.5 (a branded `ValidatedWorkspace` the interface returns, a parse that is the only constructor of the return value, whatever fits) — **which of the two carries the invariant is not.**
   ⭐ **AND THIS IS THE PROJECT'S THIRD TIME MAKING THIS EXACT CALL, ON THE SAME SAFETY RULE — cited so nobody re-litigates it.** Worker **L73**: a `process.env`-scan **denylist** was found *structurally unwinnable* for a rule-5 egress **completeness** invariant — every re-ground found more (L73 records the watched set growing **13 → 81**) — and was replaced by a spawn-env **allowlist**, complete-by-construction and drift-immune, with the denylist retained explicitly as *"defense-in-depth belt"* rather than the completeness mechanism. 2. **Does `list` reject the whole call, or drop/flag the offending row?** My default vote: **reject the whole call** for now, and say so in the report. 5. **Does the `serialization_failure`/`unavailable` retry logic anywhere treat "any err" as retryable?** A referential inconsistency is **permanently** non-retryable — retrying it forever would be a new silent-hang class. Check before adding the code.

## Lessons-logged candidates anticipated
