# /tdd brief — workspace_read_regate_at_the_repository_boundary

## Feature
Re-gate the stored `Workspace` aggregate **at the `packages/db` repository read boundary** — replacing the unchecked `row as Workspace` casts with a parse that fails closed on a referentially-inconsistent row, via a **distinguishable** typed error, on **both dialects**.

- **Architecture sections it implements:** `ARCHITECTURE.md §4` (Operational Storage — repository contract suite, dual-dialect), `ARCHITECTURE.md §5` (Policy, Security & Egress — the consumer whose documented assumption this makes true)

Lead ruling 2026-07-29: **Option A + the fail-closed-distinguishable refinement.**

## The threat model — read this before the acceptance criteria

⭐ **No production writer can *originate* a foreign nested `workspaceId`:**

| Write site | Shape | Guard | Can originate? |
|---|---|---|---|
| `apps/worker/src/composition/provisionWorkspace.ts:294` `insertIfAbsent` | whole-aggregate | `defaultWorkspace()` **parses** (`packages/contracts/src/models/workspace.ts:112`) **and wires both nested `workspaceId`s from `id`** (`:122`, `:129`); insert-only, no conflict-update | **No** — validated *and* foreign-by-construction impossible |
| `provisionWorkspace.ts:267` `updateProvisioningFields` | narrowed | `ProvisioningOwnedFields` makes a posture write untypeable (`:240-242`); values come from the already-parsed aggregate (`:264-266`) | **No** — the column is not written |
| `apps/worker/src/composition/egressRevoke.ts:68` `upsert(revoked)` | **whole-aggregate** | get-before-upsert + only the ack fields change. **No parse** — `revoked = {...ws}` where `ws = existing.value` (`:59`), an unchecked cast | **No — but it PRESERVES one** |

⇒ **Every surface this slice touches is an AMPLIFIER of a pre-existing out-of-band corruption, never an originator.** Origination stays sqlite-CLI-edit / restore-from-stale-snapshot only — **9.29's recorded accepted residual**.

⛔ **Do NOT let this become "a foreign `workspaceId` is undetected."** That is the quotable version and it is **false**. The honest one-liner is: *a missing guard whose absence makes out-of-band corruption undetectable, on fields that have consumers willing to use them as identity.*

## Why the repository boundary and not each consumer

⭐ **The decisive argument is not "one site is cheaper."** `packages/policy/src/workspace-policy.ts:7-10` and `:36` document `resolveWorkspacePolicy` as **total, needing no defensive deny, *because* "the referential pin (id ≡ egressPolicy.workspaceId ≡ providerMatrix.workspaceId) is already enforced by `WorkspaceSchema` upstream"** — and that comment sits in the layer feeding the §5 **egress veto, route resolution, and admission**.

It is true for the create path and **false** for any value arriving through the unchecked cast. **Re-gating at the read makes that documented assumption true.** A per-consumer fix leaves it false and compensates elsewhere — a load-bearing comment in the egress path asserting a guarantee the code does not provide.

⚠ **Bound it honestly** (do not over-claim the blast radius): `resolveWorkspacePolicy` keys `workspaceId: w.id` — the **top-level** id — so the veto itself is not mis-keyed. It carries the sub-models **by reference** (`:45-46`), so a consumer reading the **nested** id gets the foreign value. `apps/worker/src/composition/buildActivities.ts:854-861` is exactly that consumer, **twice**, three lines apart: `ctx.workspaceId ?? params.resolved.egressPolicy.workspaceId` and `ctx.workspaceId ?? params.resolved.providerMatrix.workspaceId`. And per that file's own words at `:851-853`, today it is *"a NO-OP; it only bites when a source classifies into a workspace distinct from the worker's default."*

## Acceptance criteria (what "done" means)
- [ ] A `Workspace` row failing the referential pin is **rejected on read** at the repository boundary, on **both** dialects — not served, not normalized. **Fail closed, never rewrite**: coercing a foreign `workspaceId` to the expected one would graft another workspace's allowlist + ack onto this workspace stamped as if it belonged (WS-8-adjacent, and legitimate-looking to every later reader).
- [ ] The rejection is a **distinguishable** typed error — separable from a store fault **and** from `not_found`. A caller can tell "this row is referentially inconsistent" from "the DB is unavailable."
- [ ] All six cast sites parse — **or** a stated subset does, with each unparsed site named in `IMPLEMENTATION_PLAN.md` task 9.36 and justified. A silent partial is the failure mode here.
- [ ] `storeBackedWorkspacePosture.ts:39-40` no longer serves a corrupt policy: today it compares `String(ws.id) !== workspaceId` and returns `egress: ws.egressPolicy` with the nested id **never checked**.
- [ ] `packages/policy/src/workspace-policy.ts:7-10,:36` is **either true or amended in this same slice.** Leaving it asserting an unprovided guarantee is the defect this slice exists to close.
- [ ] Any raw/unparsed read escape hatch is **singular, named, and pinned as singular** — a test fails if a second caller appears. An unpinned escape hatch becomes the new unchecked cast.
- [ ] Dual-dialect coverage in `packages/db/test/contract/repository-contract.test.ts` — the one suite **both** adapters must pass (§4).
- [ ] The corrupt-row fixture is built by **cast**, not by the schema (the schema correctly refuses to construct it) — mirroring `apps/worker/test/composition/provision-preserves-egress-posture.test.ts:245-249`.
- [ ] `/preflight` clean. ⛔ Report it as **"typecheck + tests clean; no lint coverage exists"** — `pnpm lint` IS `tsc --noEmit`; ESLint is absent and unconfigured. Never write "lint clean."

## RED test outline (Step 2)
In `packages/db/test/contract/repository-contract.test.ts` (runs on **both** dialects):

1. **`a_referentially_inconsistent_row_is_rejected_on_get`** — Asserts: a row whose `egressPolicy.workspaceId` ≠ `id` (inserted by cast/raw write) makes `get` resolve a typed err with the referential-inconsistency code — **not** `ok`, **not** `store_fault`, **not** `not_found`. Why: §4 read contract + L76.
2. **`the_inconsistency_error_is_distinguishable_from_a_store_fault`** — Asserts: the corrupt-row code `!==` the code produced by an unavailable/failed read. Why: the lead's refinement — a hard failure indistinguishable from an outage converts a latent inconsistency into an unexplainable one. **A boolean `isErr` is not sufficient** (contracts L80: pin the reason CODE, not the boolean).
3. **`a_consistent_row_still_round_trips`** — Asserts: the ordinary valid workspace reads back byte-identical. **The non-vacuity control** — without it, a constant-deny read passes tests 1 and 2 (contracts L80: *if I replaced the gate with a constant DENY, would anything go red?*).
4. **`providerMatrix_inconsistency_is_caught_too_not_just_egressPolicy`** — Asserts: a row foreign **only** in `providerMatrix.workspaceId` is rejected. Why: contracts **L72** — a guard applied to one field of an aggregate is a silent fail-open for its siblings, and `buildActivities.ts:858-861` consumes exactly this field.
5. **`list_rejects_or_reports_an_inconsistent_row`** — Asserts: `list` does not silently return a corrupt row typed as valid. Why: sites 2/5; a per-`get` fix that leaves `list` casting closes three of six.
6. **`updateProvisioningFields_return_is_gated_too`** — Asserts: with a corrupt row stored, the narrowed update's **returned** aggregate does not arrive cast-but-unvalidated. Why: sites 3/6 — the write method hands back posture columns it never wrote.
7. **`the_gate_does_not_normalize`** — Asserts: after a rejected read the stored row is **unchanged** — no coercion, no repair-write. Why: fail closed, never normalize (L76).

In `apps/worker/test/composition/` (consumer-side, fail-closed direction):

8. **`posture_resolver_fails_closed_on_an_inconsistent_row`** — Asserts: `storeBackedWorkspacePosture.resolve` returns its fail-closed err rather than a posture carrying a foreign policy. Why: rules 4 + 5 — the §5 veto's input.
9. **`a_diagnostic_consumer_can_report_the_inconsistency`** — Asserts: the distinguishable code survives to a caller that can name the condition (rather than being flattened into `store_fault`). Why: the operator must be able to SEE the corruption they have to repair. ⚠ If no such consumer exists yet, say so at Step 2.5 rather than inventing one — see design question 3.

## Things to flag at Step 2.5
1. **Where does the parse live — in each adapter, or in one shared helper both adapters call?** My default vote: **one shared helper**, called from all six sites. Two independent parse implementations that happen to agree read exactly like one shared implementation until one drifts — and that duplication is itself the drift risk contracts **L75** names.
2. **Does `list` reject the whole call, or drop/flag the offending row?** My default vote: **reject the whole call** for now, and say so in the report. Dropping a row silently shrinks a set a caller may be counting; contracts L~(calendar-projection) already established that "drop the bad row" is not universal. But this is genuinely arguable — if `list`'s only consumers are diagnostic, per-row reporting may be better. **Name `list`'s actual consumers before deciding.**
3. **Does a diagnostic consumer exist today that can surface "referentially inconsistent"?** If `health.egressStatus` can carry it, wire it; if nothing can, **do not invent a surface** — record it as a Future TODO and drop test 9 with a `not-tested-because:` note. The refinement's operator-visibility half may be partly a later slice, and saying so is better than a decorative pin.
4. **Is there any legitimate raw-read caller today?** My default vote: **no escape hatch until something needs one.** An unused hatch is an unpinned hole; add it when a repair path actually exists (install-doctor / repair territory — a later phase, deliberately not cited as an anchor of this slice).
5. **Does the `serialization_failure`/`unavailable` retry logic anywhere treat "any err" as retryable?** A referential inconsistency is **permanently** non-retryable — retrying it forever would be a new silent-hang class. Check before adding the code.

## Lessons-logged candidates anticipated
- **Convention candidate** — "a repository read typed by cast is the last validation boundary before its value re-crosses into a write or a policy decision; parse at the boundary, and make the error distinguishable so the operator can see what you refused." (L76's rule, promoted from one lesson's pin to a repo-wide read contract.)
- **Convention candidate** — a guard whose consumers include *both* a safety path and a diagnostic path needs **two** behaviours from one error: fail-closed for the first, legible for the second. Collapsing them is what produced 7.19.
- **Architecture-doc note candidate** — §4: the workspace read contract now rejects referentially-inconsistent rows; §5: `resolveWorkspacePolicy`'s totality assumption is now *provided*, not assumed.
- **Future TODO — operational** — the out-of-band origination path (9.29's accepted residual) still has no detection at rest; a doctor/repair check belongs to the install/repair phase (not anchored here).
