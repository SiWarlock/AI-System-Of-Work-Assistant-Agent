## ⛔ THE SITUATION, AND WHY THE OBVIOUS FIX IS THE DANGEROUS ONE

`packages/knowledge/test/gcl-projection.test.ts:401` builds a deliberately hostile fixture:
```ts
const CREDENTIAL_SHAPED_WS_ID = "https://u:hunter2@evil.example";
const workspace = defaultWorkspace({ id: CREDENTIAL_SHAPED_WS_ID, … });
```
`defaultWorkspace` → `WorkspaceSchema.parse` → the tightened brand ⇒ **`ZodError`, thrown before the test reaches
the redaction gate it exists to verify** (`serve_projection_denial_routes_through_the_redaction_gate`).

⛔⛔ **DO NOT MAKE THE FIXTURE A VALID SLUG. That turns the suite GREEN while silently deleting the rule-7
coverage** — the file keeps its name, the test keeps passing, and it no longer tests that a credential-shaped id
is redacted. `L82`'s completion badge on a rule-7 surface, and it is the path of least resistance.
⛔ **DO NOT WEAKEN THE BRAND.** The shape is correct. **This is the shape working.**

⭐ **WHY THE TEST IS STILL LOAD-BEARING AFTER THE BRAND SHIPS — this is the reasoning, not just the verdict.**
`### 24.84` states that **neither boundary closes PRE-EXISTING ROWS**; write-boundary validation is
**prospective**. ⇒ **a row already in a user's DB carrying a credential-shaped id is precisely the population the
write gate cannot reach, and this test is the only thing asserting such a row is redacted on READ.** The brand
does not empty that population — it makes it **unconstructible in a test**, which is backwards.
⇒ ⭐⭐ **THE DURABLE FRAMING (lead-adopted): *the write gate and the read gate are genuinely different controls
and must not be collapsed.* The tightened definition's first act was to disarm the test proving the fallback
works — that is evidence FOR the definition and AGAINST collapsing the two gates.**

## ⛔ MECHANISM — A NAMED CONSTRUCTOR, AND THE CAST IS FORBIDDEN

**Lead ruling, on this project's own measurement from today:** `L179`/`### 24.87` established that **`as X` casts
are INVISIBLE to compiler enumeration.** ⇒ ⛔ **a bare `as` cast here would deliberately manufacture the exact
blind spot the team banked a lesson about this morning — on a rule-7 fixture, where it is least affordable.**

⇒ **Build a named, greppable helper** — e.g. `unsafeWorkspaceIdForTest(raw: string): WorkspaceId` — that bypasses
the brand deliberately. ⭐ **A cast is anonymous; a NAME is evidence.** It carries its own docblock and declares
intent at **every** call site, not only where a comment happens to sit.

⛔ **THE DOCBLOCK MUST NAME THE POPULATION, NOT JUST THE BYPASS.** Per the standing ruling that an assertion
about an inert guard must say what makes it load-bearing: it must say **this models a row written BEFORE the
validator existed — the one population the write gate cannot reach.** ⚠ **Without that sentence the next reader
deletes the helper as an obstacle to a clean brand, and the deletion will be GREEN.**
