## Why these two bundle

They bound the **same claim from two directions**. After 9.23, "the egress revoke is durable" is true *absent a
concurrent revoke* (9.30) *and absent a second workspace on the same vault root* (9.31). Neither is meaningful
alone — a reader asking "is the revoke durable?" needs both answers or gets a half-truth. Same file, same
function, same reviewer context.

⚠ **Both are rule-5-adjacent.** If either turns out to be **live-exploitable** rather than latent, split it out,
give it its own commit, and say so at Step 9.

## Verified premises (falsify first)

1. **9.30:** the existence-check `get` → `upsert` is a non-atomic read-modify-write, and both adapters do an
   unconditional `onConflictDoUpdate`. A `revokeEgressAck` landing between them is silently reverted — 9.23's
   own defect narrowed to a race, still with no audit row.
2. ⚠ The sibling `workspaceRegistry.ts:40-46` carries an explicit `arch_gap (concurrency)` note for exactly this
   class; `provisionWorkspace` carries none. **Read that note before designing** — the two should end up
   consistent, and the sibling may already encode the house answer.
3. **9.31:** `createWorkspace` takes a **caller-chosen `id`** and nothing enforces uniqueness on
   `markdownRepoPath`, so a *new* `employer_work` workspace pointed at the same vault root is a fresh create ⇒
   freshly seeded `ack=true`. Review did **not** establish a live path binding jobs to a workspace by vault path
   — so this is hardening, not a demonstrated exploit. **Confirm or overturn that** as your first move on 9.31;
   if a live path exists, the severity changes and it splits out.

## Acceptance criteria

**9.30 — the race**
- [ ] A revoke interleaved between the existence check and the write either **wins** or **fails loudly** — never
      silently reverts.
- [ ] The chosen mechanism (compare-and-set, insert-only on the create branch, or a documented `arch_gap`
      consistent with the sibling) is stated in-code with its reasoning.
- [ ] 9.23's and 9.29's behaviour is unchanged — assert, don't assume.

**9.31 — the bound**
- [ ] Either a second workspace cannot silently bind an already-provisioned vault root, **or** the limitation is
      recorded where a reader asking about revoke durability will meet it.
- [ ] Whichever way it goes, the answer to "is the revoke durable?" is stated **with its bounds**, never
      unqualified.

- [ ] `/preflight` clean.
