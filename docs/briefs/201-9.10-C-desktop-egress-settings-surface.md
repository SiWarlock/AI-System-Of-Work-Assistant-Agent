# /tdd brief — workspace_egress_settings_surface (9.10-C)

## Feature
A workspace-settings **egress** surface in the Electron renderer that shows each workspace's raw-cloud-egress posture (acknowledged vs not, zero-egress-only) read from the worker's UI-safe projection, and offers exactly ONE mutating affordance — the fail-SAFE **revoke** — dispatched as an authed worker command. The renderer never flips policy locally, and there is deliberately **no re-ACK affordance** (see the safety scoping note).

## ⚠ SAFETY SCOPING — revoke ONLY, no re-ACK (do not "complete the toggle")
The egress **ack** direction (turning employer raw-cloud egress ON) is a **rule-5 crossing** and is owner-gated: it was executed once, deliberately, as a provisioning-time default-seed (`bcde3d61`) plus the fail-safe revoke command (`225c10ca`). The worker exposes **no re-ack command** — by design. Handoff 016 loosely says "revoke/re-ack"; the shipped surface for this slice is **status + revoke**.

So: **do not** build a two-way toggle, an optimistic local flip, or a "re-enable" button, and do not add a worker procedure to make one possible. If the UI needs to say something about the OFF state, it says the re-enable path is owner/provisioning-gated. If you believe the surface is unusable without re-ack, that's a **Step-2.5 flag → escalation**, not a design you settle yourself.

## Acceptance criteria (what "done" means)
- [ ] A `workspace-settings` egress surface renders, per workspace, the acknowledged/not + zero-egress-only posture from `health.egressStatus` — no derived or guessed posture, no local default-true anywhere.
- [ ] The surface renders an **honest empty/unknown state** when the query errs or the worker is unavailable (fail-closed presentation: unknown is NOT shown as "acknowledged"; treat an error as "posture unavailable", never as permission).
- [ ] The revoke affordance calls `egressCommand.revokeEgressAck` through the live handle and **re-renders from the command's returned status** (or a re-hydrate) — the renderer never mutates the posture in local state.
- [ ] Revoke is confirmed before dispatch (it's a policy change) and is **not** offered for a workspace whose ack is already OFF.
- [ ] A revoke failure surfaces a typed, non-leaking error and leaves the displayed posture unchanged (no optimistic flip).
- [ ] No secret, no raw content, no absolute path, and no field outside the three allowlisted ones reaches the renderer or any log/console sink (rule 7 + the UI-safe allowlist).
- [ ] The surface is registered on the route union and reachable from the shell's navigation — not an orphan component.
- [ ] `pnpm build:sow` then `/preflight` clean (desktop dist is stale otherwise).

## RED test outline (Step 2)
Tests in the desktop renderer test location (DOM-less node tsconfig for logic; follow the area's existing renderer-test convention — see desktop LESSONS §3 on the `test/` DOM-less config):

1. **`renders_acknowledged_and_zero_egress_from_query`** — Asserts: given a faked `egressStatus` returning ack=true / zeroEgressOnly=false, the surface shows the acknowledged posture; given ack=false, it shows not-acknowledged. Why: REQ-S-002 — posture must be *surfaced*, per workspace.
2. **`query_error_shows_unavailable_not_acknowledged`** — Asserts: an `err` result renders an explicit unavailable/unknown state and does NOT render "acknowledged". Why: fail-closed presentation — an unknown posture must never read as permission (safety rule 5's presentation analog).
3. **`revoke_dispatches_worker_command`** — Asserts: confirming the revoke calls the handle's `revokeEgressAck` exactly once with the selected workspace. Why: the renderer never flips policy locally (REQ-S-004 discipline / §11).
4. **`revoke_renders_from_command_result`** — Asserts: the post-revoke display comes from the command's returned status (ack now OFF), not from local optimistic state. Why: the worker is the single source of posture truth (9.10-A store-backed single-source).
5. **`revoke_failure_leaves_posture_unchanged`** — Asserts: an `err` from the command surfaces a typed error and the displayed posture is unchanged; no optimistic flip. Why: no false "revoked" claim; the fail-safe direction must still be honest about failing.
6. **`revoke_not_offered_when_already_off`** — Asserts: ack=false ⇒ no revoke affordance dispatched/enabled. Why: no no-op policy commands; keeps the audited command path meaningful.
7. **`no_reack_affordance_exists`** — Asserts: the surface exposes no path that would set the ack ON (inventory/grep pin over the surface's client calls: `revokeEgressAck` only). Why: the ack direction is an owner-gated rule-5 crossing — pin it so a later slice can't quietly add it.
8. **`renderer_receives_only_allowlisted_fields`** — Asserts: the surface reads only `workspaceId` / `employerRawEgressAcknowledged` / `zeroEgressOnly`, and a projection carrying an extra/leaky field does not surface it. Why: the UI-safe allowlist + rule 7 (mirrors the worker-side leak-guard test at `systemHealth.test.ts:169-173`).
9. **`route_registered_and_reachable`** — Asserts: the route union member exists and `App.tsx` renders the surface for it. Why: Step-7.5 reachability — an unrouted surface is dead code.

## Things to flag at Step 2.5
1. **Route granularity.** (a) a new top-level `workspace-settings` surface whose first pane is egress, (b) a dedicated `workspace-egress` route, (c) fold the status (read-only) into the existing `system-health` surface and put revoke in settings. My default vote: **(a)** — the plan names `surfaces/workspace-settings/egress.tsx`, and a settings container is where a policy mutation belongs; System Health stays a read surface. Flag if the shell's nav model makes (a) expensive.
2. **Which workspaces are listed.** (a) only the active/scoped workspace, (b) all configured workspaces with per-row posture. My default vote: **(b) all configured, per-row** — REQ-S-002 is about seeing the posture *per workspace*, and the employer-vs-personal asymmetry is the whole point of the surface. Confirm a workspace list is already available to the renderer via an existing UI-safe read; if it isn't, fall back to (a) and flag the missing read rather than inventing one.
3. **Store slice vs surface-local state.** My default vote: **surface-local, hydrate-on-mount** — posture is read-on-demand, not a live-streamed projection, so it doesn't need to widen `UiSafeStoreState`. Flag if the shell's hydration model expects everything in the store.
4. **Confirmation UX for a policy change.** ⚠ Per the project's browser/dialog discipline, do **not** use a native `confirm()`/`alert()`. My default vote: **an in-surface two-step confirm** (click → explicit confirm control), copy naming the effect ("employer raw content will no longer be sent to the cloud provider for this workspace").
5. **Empty/unknown wording.** My default vote: **"egress posture unavailable"** for an error and an explicit "not acknowledged — raw employer content is not sent to cloud providers" for ack=false. The one thing that must never appear is an implied "allowed" for an unknown state.
