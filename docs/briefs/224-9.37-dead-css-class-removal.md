## Feature
Delete the orphaned `.sow-pill--zero-egress` CSS rule from the desktop renderer. It was pre-staged for a follow-up that has since shipped **under a different class name**, so it is now genuinely dead rather than reserved.

## Use case + traceability

## Why this is a deletion and not a reservation
Brief 205 pre-staged `.sow-pill--zero-egress` for the 9.10-C bullet-1 follow-up **and wrote the disposal condition itself**: *"if the follow-up takes a different shape, delete it rather than leaving it orphaned."* That follow-up **shipped** (`cda4d2f4`) and used **`sow-pill--egress-scoped`** instead. So the condition is met, by its own author's terms. The Phase-9 reachability audit classified it as the area's **single genuinely-unreachable symbol** — everything else unreachable there is dormant-by-design with a citation.

⛔ **Cited by CLASS NAME, with no line number, deliberately.** The tracker previously said `styles.css:1960`; it had already rotted to `:1942` by the time the audit read it. A line number in durable prose rots by construction, and this one points at something about to be deleted.

## Why FIRST, before 9.25 (lead ruling)
9.25 carries **stop-conditions** — it may legitimately **not ship** and instead report a finding. **Work that depends on shipping must not ride a slice that may halt.** If this deletion rode 9.25 and 9.25 halted, the CSS is either stranded behind a halted slice or commits anyway — and then the commit reads as *partial work* rather than as a *clean finding*, which is precisely the ambiguity the stop-condition exists to prevent. So: this lands first, own commit, deck cleared.
