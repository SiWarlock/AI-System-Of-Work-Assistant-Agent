# /tdd brief — typed_partial_scaffold_state (9.21-A, worker producer leg)

## Feature

Make a **partially-provisioned workspace a first-class typed outcome** of `provisionWorkspace` instead of collapsing into the undifferentiated `store_fault` code — so the desktop consumer (9.21-B) can distinguish *"nothing was created"* from *"the config row landed but the registry union did not"*, and can offer resume rather than a dead end. Also **pin the resume path that already works**, so it cannot silently regress.

## The defect, with file:line evidence (verify every claim — these are premises, not instructions)

`provisionWorkspace` (`apps/worker/src/composition/provisionWorkspace.ts:134-282`) has **four durable steps** and **five distinct failure points**, and every store-side one returns the same code:

| Site | Line | Returns | Leaves behind |
|---|---|---|---|
| aggregate validation | `:155` | `invalid_workspace` | nothing |
| existence-check `get` fault | `:172` | `store_fault` | nothing |
| same-type `updateProvisioningFields` fault | `:247` | `store_fault` | **the prior row, intact** |
| same-type `registerWorkspace` fault | `:252` | `reg.error` | **updated config row, NOT registered** |
| create `insertIfAbsent` fault | `:268` | `store_fault` | nothing |
| create concurrent-row | `:273` | `store_fault` | a row someone else created |
| create `registerWorkspace` fault | `:279` | `reg.error` | ⛔ **config row written, NOT registered — the partial** |

`ProvisionWorkspaceError` is only three codes (`:112-117`): `invalid_workspace` · `workspace_type_immutable` · `store_fault`.

⭐ **The partial state is already acknowledged in-code and deliberately made fail-closed** — `:256-259`: *"Insert the whole seeded aggregate FIRST, so a later union fault leaves the workspace invisible (fail-closed), never registry-known-but-config-less."* So the durable partial is **safe** (invisible to scoped reads — WS-8 holds) but **stuck and indistinguishable**: the caller sees `store_fault`, identical to "nothing happened."

⭐ **And the resume ALREADY WORKS** — `:249-252`: *"Union into the registry exactly as the create path does — a re-provision must still repair a workspace that was written but never registered."* So the Done-when clause *"re-run resumes idempotently"* is **already satisfied by shipped code.** ⛔ **Do not rebuild it. VERIFY and PIN it** — that is this slice's cheapest, highest-value half, because nothing currently proves it and it is one refactor away from silently regressing.

## ⚠ A structural guarantee you must NOT weaken

`ProvisionedWorkspace.registryMember` is typed as the **literal `true`** (`:120-125`, *"registry-member by construction"*). That literal is load-bearing in the same way worker **L31** describes: it makes "provisioned but unregistered" **structurally unrepresentable as a success**. ⛔ **Widening it to `boolean` to express a partial would delete a real invariant to model a failure as a success.** A partial is not a success. Keep `ok` meaning fully-provisioned-and-registered.

## Acceptance criteria (what "done" means)

- [ ] A `registerWorkspace` fault on the **create** path returns a distinct typed outcome carrying (a) that the config row IS durably written and (b) that registry union is the incomplete step — never the bare `store_fault` it returns today
- [ ] A `registerWorkspace` fault on the **same-type** path returns that same distinct outcome
- [ ] `ProvisionedWorkspace.registryMember` remains the literal `true` — a partial is NEVER an `ok` (typecheck-enforced; a test that constructs a partial as `ok` must not compile)
- [ ] The other four store-fault sites keep returning `store_fault` — this slice **narrows** the taxonomy, it does not re-label unrelated faults
- [ ] **Resume is pinned:** a workspace left config-written-but-unregistered, re-provisioned same-type, ends **registered**, with `egressPolicy` **byte-identical** to the stored (revoked) one — i.e. the resume path cannot restore a revoked ack (the 9.23/9.30 guarantee, re-pinned at the site that now becomes routine)
