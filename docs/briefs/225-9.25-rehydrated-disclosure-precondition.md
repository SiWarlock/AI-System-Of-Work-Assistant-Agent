## ⛔ TWO STOP-CONDITIONS (lead-imposed). Either one fires ⇒ STOP AND REPORT; do not ship around it.

**STOP-CONDITION 1 — the pin must be MECHANICALLY NON-VACUOUS.**
Branch (B) closes on a **negative** claim ("no restore path exists"), and **a pin on a negative claim is trivially easy to write such that it can never fail.** That is a decorative pin: it reports "checked" forever while checking nothing (contracts **L75** — a negative guard that has never failed is indistinguishable from one that cannot fail).
- ⇒ **The pin must FAIL when the condition it guards is violated, and you must SEE it fail.** Concretely: add a *fake production* consumer of the seed/`turns` seam, watch the pin go **RED**, then revert. Report the mutation you applied, that it reached the code under test, and the passing/failing counts (contracts L75's three-state protocol).
- ⛔ **If no such mechanical anchor exists — if you cannot construct a pin that fails on a real violation — that is a FINDING, not a reason to ship a decorative pin.** Say so and stop. A recorded "we could not pin this" is worth more than a green test that proves nothing.
- ⚠ On current evidence an anchor **does** exist (a tripwire over the seam's production callers, which fails the moment one appears), so I expect this condition **not** to fire — but I am not the one with the file open, and per **L102** the first question is whether this is even the kind of claim a test can pin. If it is not, `accepted: not mechanically enforceable` plus the evidence is the honest closure, and **no future slice is owed a pin.**

**STOP-CONDITION 2 — the closure must not read as "disclosure-on-rehydrate is solved."**
Branch (B) closes the *task*, not the *risk*. The moment a restore path is built, this becomes live case 3 from 9.24: a real, plausible Employer-Work cloud answer rendered **silently**, with nothing in the pipeline to catch it.
- ⇒ The closure text **must name which branch it took**, must state that **9.25 remains a dormant precondition on any future restore work**, and must not be phrasable as "handled."
- ⚠ **This is a rule-5 surface.** A closure that reads as solved is exactly the false-reassurance class this project keeps hitting — and the danger is asymmetric: an over-cautious record costs a re-read, an over-confident one removes the guard.
