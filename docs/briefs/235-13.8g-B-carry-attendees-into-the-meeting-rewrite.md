# /tdd brief — carry_attendees_into_the_meeting_rewrite

## Feature
Thread the meeting's attendee data through `normalizeAttendees` (13.8g-A's dormant producer) into
`rewriteVaultForMeeting`'s `entityRefs`/`identifierOnlyRefs`, so the meeting-path living-vault rewrite
grounds against real person entities instead of an empty candidate set. Ships DORMANT (the whole
meeting-rewrite path is gated + unbound).

## ⛔ READ FIRST — THE TASK'S OWN PREMISE IS WRONG, AND THE CORRECTION CHANGES THE FILE LIST

`#### 13.8g` (`IMPLEMENTATION_PLAN.md:1851-1853`) describes leg B as *"carry the meeting's attendee
strings into the 13.8f-B call"* and names `correlateMeeting.ts` in its Files line. **Both halves are
wrong, established from source before dispatch. Do not follow them; follow this section.**

**(1) THERE ARE NO RAW ATTENDEE STRINGS ANYWHERE IN THE PIPELINE.** The task's Files line says
*"attendees are rendered-only free-text strings at `meetingOutputs.ts` L157/L169-170."* Those lines read
**`fields["attendees"]`** — an entry in `ValidatedExtraction.fields`, i.e. **post-model, schema-gated,
`validateNoInference`-gated candidate data**, typed `ExtractionField<unknown>` =
`{ value: T | typeof TBD; evidenceRef?: string }` (`packages/domain/src/validation/no-inference.ts:30-33`).
That is **not** the raw untrusted string array `normalizeAttendees` was written against
(`attendee-refs.ts:2-3` describes its input as free-text strings; `:173` requires `Array.isArray(raw)`
and `:194` requires `typeof entry === "string"`).
⇒ **Scope of the negative, stated so you can refute it in one command** (contracts L100):
`grep -rin "attendee" --include="*.ts" --include="*.tsx" packages/*/src apps/*/src | grep -v /dist/`
returns hits in exactly two functional places — `packages/knowledge/src/synthesis/*` (13.8g-A's own
module + prose) and `packages/workflows/src/activities/projections/meetingOutputs.ts`
(`:83` the frontmatter key list, `:157`/`:170` the render). **Everything else is prose.** No raw
attendee-string producer exists. If you find one, that is a finding — say so rather than working around it.

**(2) `correlateMeeting.ts` STRUCTURALLY CANNOT CARRY IT — do not add a `CorrelationSignals.attendees`
field.** The task's Files line proposes exactly that. But correlate runs **BEFORE** extraction:
`workflows/meetingCloseout.ts:250` correlate → `:298` agent extraction → `:309` validate → `:326`
buildOutputs. At correlate time the only content in scope is `MeetingCloseoutContext.source: SourceEnvelope`,
and **`SourceEnvelope` has no attendees field** (verified: `grep -n "attendee"
packages/contracts/src/models/source-envelope.ts` → 0 hits; its only content-bearing field is `body?: string`).
⇒ **Adding an `attendees` field to `CorrelationSignals` would create a field nothing can populate** — the
L106 shape this project keeps re-instantiating, and it would be minted by a brief that exists to avoid it.

**(3) WHAT ACTUALLY WORKS, and why it is a clean fit rather than a workaround.** `validated.fields` is in
scope **in the same function as the rewrite call**: `buildOutputs.ts:181` reads `validated.fields[...]`,
`:197` passes `validated` to the projection, and the `deps.meetingVaultRewrite.rewrite(...)` call sits at
`:260-268` — same scope, no plumbing needed to reach it. And `normalizeAttendees(raw: unknown)` is
**TOTAL and takes `unknown` by design**, returning `{refs:[],identifierOnlyRefs:[],withheld:[]}` on a
non-array (`attendee-refs.ts:172-173`) — so handing it `validated.fields["attendees"]?.value` is safe on
every shape it can hold (a string, an array, the `TBD` sentinel, or absent) **without a single new guard**.
That totality is not luck; it is what the 13.8g-A author built it for.
