## Acceptance criteria (what "done" means)
- [ ] `refreshTaskRollup({workspaceId}, {tasks, readModels, now})` reads `tasks.listByWorkspace(wsId)` → ranks deterministically → maps to `UiSafeTaskRollupItem[]` (drops `provenanceOrigin`/raw fields — only the UI-safe fields) → `readModels.put({readModelKey: task_rollup, workspaceId, data:{items}, rebuiltAt})`. Full-refresh SUPERSEDES; returns a never-throws typed `Result`; fail-SAFE (L77 — never blocks a commit).
- [ ] **Deterministic ranking (REQ-F-017 never infers):** priority asc `p0 < p1 < p2 < p3 < UNSET-last` → then dueDate earliest-first (unset last) → then `taskId` asc final tiebreak (CI-stable, mirrors the RRF id-asc tie-break L26). An absent `Task.priority` ⇒ the item's `priority` is ABSENT (unset) — never guessed.
- [ ] **WS-8 (SAFETY):** the write key is the served `workspaceId`; the positive-keying leg holds (a task stored under `(task_rollup, A)` is served for A; B reads empty); `listByWorkspace` reads the authorized ws only; the emitted `UiSafeTaskRollup` carries NO `workspaceId` anywhere.
- [ ] Terminal statuses (`done`/`cancelled`) are EXCLUDED from the rollup (a completed task isn't a priority) — Step-2.5 Q4.
- [ ] The serve path `query.taskRollup(wsId)` re-validates each result via `sanitizeTaskRollup` (re-parse `UiSafeTaskRollupSchema`, fail-closed drop) — empty-until-producer.
- [ ] Producer-side cap at the schema `.max(200)`; the read `sanitizeTaskRollup` re-caps.
- [ ] **Dormant/empty-until-data:** the producer ships NOT bound in `composition/`/`boot.ts` (mirror `calendarProjection` 9.9a) — no `TaskRow` populator exists yet (13.15 built the repo, not a writer), so the serve path is empty-until-data; the trigger binding is a named follow-up (Step-2.5 Q3).

## RED test outline (apps/worker/test/api/projections/taskRollupProjection.test.ts)
1. **`ranks_priority_then_due_then_id`** — a task set → items ordered p0<p1<p2<p3<unset, dueDate earliest-first within a priority, taskId asc final. Asserts: deterministic order. Why: §11 pre-ranked + REQ-F-017.
2. **`absent_priority_stays_unset`** — a task with no priority → item `priority` absent, sorted last, never a guessed value. Why: no-inference safety.
3. **`excludes_terminal_statuses`** — done/cancelled tasks are omitted. Why: Q4.
4. **`ws8_positive_keying`** — tasks for ws A stored under `(task_rollup,A)`; a `taskRollup(B)` read returns empty. Asserts: no cross-workspace blend. Why: WS-8 (SAFETY).
5. **`emitted_rollup_has_no_workspaceId`** — the serialized `UiSafeTaskRollup` carries no `workspaceId` field. Why: WS-8 display boundary.
6. **`sanitize_drops_leaky_row_fail_closed`** — a malformed/leaky stored row → dropped on read (re-parse). Why: fail-closed read.
7. **`producer_fail_safe_never_throws`** — a repo fault / `readModels.put` fault → typed Result, no throw, never blocks. Why: L77.
8. **`cap_at_200`** — >200 tasks → capped. Why: flood-bound.
9. **`dormant_producer_unbound`** — grep proves `refreshTaskRollup` is not bound in `composition/`/`boot.ts`. Why: dormant.
