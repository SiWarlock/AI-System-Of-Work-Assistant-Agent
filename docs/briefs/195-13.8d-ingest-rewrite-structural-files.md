# /tdd brief — living_vault_ingest_rewrite (13.8d)

## Feature
The living-vault ingest-rewrite LOGIC — a PURE multi-entity orchestrator that makes an ingested source "rewrite the vault": resolve the source's entities (13.8a `resolveEntity`) → `planSynthesis` (13.8c) → emit a **multi-entity** `KnowledgeMutationPlan` set (0–2 KMPs) + **structural-file parity** mutations (index.md section-regen + op-log) — all routed THROUGH KnowledgeWriter (sole writer, rule 1). Plus a per-run **digest receipt** (enumerable revisions for one-action batch-undo). DORMANT — the wiring into `runSourceIngestion` is a separate worker binding (L24).

## Acceptance criteria (what "done" means)
- [ ] `rewriteVaultForSource(source, deps)` (PURE, never-throws): resolves the source's referenced entities in STABLE source order, dedups by resolved notePath, then makes a SINGLE `planSynthesis` call per run merging to ≤2 KMPs (one AUTO / one PROPOSE — preserves the 13.8c 0–2 invariant + one digest). An ingest **updates ≥1 EXISTING related note** (not just creates) when an entity resolves.
- [ ] **Structural-file parity (KN-12), as KMP mutations through KW** (never a direct/2nd writer): `index.md` = a per-section `NotePatch` regenerating ONLY changed `- [[Note]] - desc` sections (KN-7-safe, minimal diff); op-log = append `Logs/YYYY-MM-DD.md` (NoteCreate/patch) + a `log.md` pointer patch. All emitted as mutations in the plan set / a structural-file port (Q-a), routed to KW.
- [ ] **Digest receipt + batch-undo:** the run returns `IngestRewriteReceipt{runId, plans, revisionIds, autoCount, proposeCount}` — the `revisionIds` are the enumerable one-action-undo unit (the actual revert is a worker-side operation over the revision store, out of this slice; this slice guarantees the run's revisions are grouped/enumerable).
- [ ] **@user confinement inherited** from 13.8c (`planSynthesis` symmetric fail-closed allowlist — `isSafeRegionId`); no path this slice adds can patch a `@user`/human region; structural-file writes target `@generated`/vault-surface regions only.
- [ ] **No-inference (REQ-F-017):** inherited via `planSynthesis` (un-evidenced owner/date → TBD); structural-file content is derived (note titles/links), never invents a claim.
- [ ] **Security item (i) — `describe()` enumerates BOTH families:** the injected `SynthesisSectionPort`/`NoteRegionDescriptor.generatedRegionIds` contract REQUIRES enumerating BOTH `kw:region` AND `@generated` ids (so a `refresh` can never overwrite writer content mislabeled as fresh); document + type this in-slice (`parseSections`/`listRegionIds` already unify them). The live-vault backing impl is wire-time.
- [ ] **Security item (ii) — KW create marker-neutralization (own SAFETY commit):** `renderCreate` (`writer.ts:479`) neutralizes `NoteCreate.body` markers on create (today it does not; ingest-rewrite raw creates need it — the planner's `new_note` already wraps via `renderGeneratedRegion`). A content-embedded `kw:region`/`@user` marker in a create body can never forge a region boundary (L9/L14 fixpoint neutralization).
- [ ] **Security item (iv) — per-array candidate bound (L31):** length caps on `regions[]`/`frontmatter[]`/`entityRefs[]`/`links.refs[]` before fan-out (flood-bound).
- [ ] **(Security item (iii) — model-controlled notePath realpath containment (L17) — DEFERRED to the worker binding**; note it as a wire-time requirement, not built here.)
- [ ] PURE over injected ports; TOTAL never-throws; DORMANT (no `runSourceIngestion`/workflows/apps edit; zero non-test prod importers). All new tests pass; `/preflight` clean.
