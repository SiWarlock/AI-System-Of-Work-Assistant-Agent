## Acceptance criteria (what "done" means)
- [ ] A run whose receipt carries a non-empty `refusals` produces **one** observable, code-only signal naming the refusal reason code(s) and the workspace — no path, no title, no entity name (rule 7).
- [ ] A benign run (`refusals: []`) produces **zero** sink invocations — a quiet run stays quiet.
- [ ] **A run that is refused AND then rejected by containment still surfaces its refusals.** The `path_escape` / WS-8-mismatch early-returns at `living-vault.ts:141-152` must not swallow them. This is the worker-side analog of the producer's own hoisted-accumulator reasoning at `ingest-rewrite.ts:112-115`: *a fault after admission must not discard what was already refused,* or a hostile run that hijacks paths and then trips a later guard becomes byte-identical to a benign one again.
- [ ] A **throwing/rejecting** sink does not change the returned `Result` (best-effort, L25/L53) and does not escape as an unhandled rejection.
- [ ] The sink dep is **optional**; unbound ⇒ byte-equivalent to today (assert zero invocations of the factory/sink on the unbound path).
- [ ] The reason codes crossing the seam are exactly the producer's union — `"structural_surface" | "unsafe_shape"` (`grounded-path.ts:52-56`). No worker-local re-declaration of that union (single-source it via a type-only import, L5/L37).
