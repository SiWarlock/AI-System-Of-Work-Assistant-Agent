# /tdd brief — open_in_vault_path_scoped

## Feature
Open-in-Obsidian / reveal-in-vault for workspace repos + the Global/Coordination repo, invoked through the typed preload IPC bridge and PERFORMED IN MAIN: the renderer requests open-by-path only; **main opens/reveals ONLY a path whose realpath is contained within a configured workspace/global repo root, rejecting every other request (no arbitrary path open)**. Self-contained desktop slice; the parallel-start for the Phase-9 "make it real" arc (zero data dependency).

## Acceptance criteria (what "done" means)
- [ ] A PURE, electron-free `guardVaultPath(requestedPath, roots, realpath)` (in `apps/desktop/main/open-in-vault.ts`) returns a typed `Result<{ absPath }, reject>`: reject NUL/malformed → lexically `resolve` the path and require `full === root || full.startsWith(root + sep)` for ≥1 configured root → realpath BOTH the path and the matched root(s) and RE-CHECK containment on the real paths → for `open`, require a regular file (injected `stat`/`isFile` seam). Injected `realpath` (+ `stat`) seams so it's node-testable with zero real fs.
- [ ] **SAFETY PIN — main opens/reveals ONLY a realpath-contained vault path.** Each of these fails closed to a typed reject with NO filesystem side effect, NO disclosure of why, and NEVER throws: (a) a path outside every configured root; (b) a `../` traversal escaping a root; (c) a symlink whose realpath escapes a root (caught by the realpath layer, NOT the lexical one); (d) a sibling-prefix path (`/vault-evil` vs root `/vault` — the `+ sep` guard); (e) a NUL byte / malformed path; (f) a non-existent or non-file target (for `open`).
- [ ] A contained regular file resolves to `ok({ absPath })` and the main handler invokes the real `shell.openPath(absPath)` (open) / `shell.showItemInFolder(absPath)` (reveal).

## RED test outline (Step 2)
Tests in `apps/desktop/test/main/open-in-vault.test.ts` (pure guard, injected fake `realpath`/`stat`):

1. **`contained_file_resolves_ok`** — Asserts: a real regular file under a configured root → `ok({ absPath })`. Why: REQ-UX-003 happy path.
2. **`outside_all_roots_rejects` (SAFETY)** — Asserts: a path under no configured root → typed reject, no `shell` call. Why: §5 no-arbitrary-open.
3. **`traversal_escape_rejects` (SAFETY)** — Asserts: `<root>/../etc/passwd` → reject (lexical layer). Why: §5 traversal containment (mirror `resolveAppRequest`).
4. **`symlink_escape_rejects` (SAFETY)** — Asserts: a path lexically under root but whose injected `realpath` returns an out-of-root target → reject (realpath layer — the one `resolveAppRequest` lacks). Why: §5 symlink escape (mirror copilotVaultRead / L17).
5. **`sibling_prefix_rejects` (SAFETY)** — Asserts: root `/vault`, path `/vault-evil/x.md` → reject (the `+ sep` guard, not a bare `startsWith`). Why: §5 shared-prefix.
6. **`nul_or_malformed_rejects` (SAFETY)** — Asserts: a NUL-byte / malformed path → reject before any fs seam. Why: §5 malformed input.
7. **`non_file_target_rejects_for_open`** — Asserts: a contained path that is a directory / non-existent (injected `stat`) → reject for `open`. Why: open targets a real file.
8. **`guard_never_throws_on_seam_fault`** — Asserts: an injected `realpath`/`stat` that throws → the guard returns a typed reject, never propagates. Why: §16 never-throws.
9. **`multi_root_containment`** — Asserts: with ≥2 roots, a file under the 2nd root resolves ok; a file under neither rejects. Why: the roots-set contract (workspace repos + Global/Coordination).

Plus: confirm `preload-inventory.snapshot.test.ts` (existing) re-greens with the 2 new channels.

## Things to flag at Step 2.5
1. **Roots source (the allowlist the guard checks against).** Desktop main today reads only a SINGLE `SOW_VAULT_ROOT` (`main/index.ts:101`); the contract has `vaultRootPaths` (slug→abs) but desktop doesn't parse it. (A) `roots = [vaultRoot]` — minimal, matches current reality, no new env, Global/Coordination repo is a subdir under it; (B) parse `SOW_VAULT_ROOT_PATHS` (JSON) → `Object.values(...)` + the Global/Coordination root (desktop needs its OWN parser — layer rule forbids importing the worker's `parseVaultRoots`). My default vote: **(A) minimal**, and keep the pure `guardVaultPath` **roots-agnostic** (takes `roots: readonly string[]`) so the source decision never touches the TDD core — (B) becomes a trivial wiring follow-up when multi-workspace desktop config lands.
2. **Channel granularity.** Separate `vault:open` + `vault:reveal`, or one `vault:open` with a `{ reveal?: boolean }` mode? My default vote: **separate channels** — clearer, one maps to `shell.openPath` and one to `shell.showItemInFolder`, and each is an explicit inventory entry.
3. **Slice split.** One cohesive slice (guard + preload + main + inventory), or guard-first then wiring? My default vote: **one cohesive slice** given the small size — BUT the guard's safety assertions (tests 2-6, 8) are the safety surface, so if any wiring churn risks it, the guard lands as its OWN commit first (never bundled with unrelated churn — desktop CLAUDE.md TDD protocol).
