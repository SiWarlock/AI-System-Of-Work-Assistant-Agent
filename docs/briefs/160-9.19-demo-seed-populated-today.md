# /tdd brief — dev_demo_seed_populated_today

## Feature
A DEV-ONLY, flag-gated fixture that populates the full Global Today read-model with representative sample data — so the owner can run `./dev.sh` (with `SOW_DEMO_SEED=1`) and browse a fully-populated daily briefing (dashboard cards, recent changes, ingestion inbox, projects, nav counts) with **ZERO** model calls, egress, arming, or Keychain. Pure local read-model fixtures — never Markdown, never KnowledgeWriter, never a real-run path.

## Use case + traceability
- **Task ID:** 9.19 — a dev-tooling task (owner wants to SEE a populated dashboard without extraction/arming)
- **Architecture sections it implements:** `ARCHITECTURE.md §11` (Today surfaces) · `§10` (read-model serving) · `§5` (WS-8 registry, safety rule 4 — the dev fixture stays read-model-only) · `§16` (never-throws at boot)
- **Related plan decision:** the 9.4 "empty-until-data, no seed" decision — the demo-seed is the OPT-IN dev exception to it, strictly gated (not an arch anchor; a plan-task reference).
- **Related context:**
  - **The precedent to mirror + extend: `apps/worker/src/composition/provisionDev.ts`** — a DEV-ONLY provisioner that writes REAL `read_models` rows (workspace / project / project_dashboards / recent_changes) + registers the workspace (WS-8), gated behind a boot flag, "never writes Markdown, never routes a semantic mutation (KnowledgeWriter's sole job), never touches secrets." Reuse its shape-correct upsert helpers (`upsertCardRow`, `upsertProjectRow`, `upsertRecentChangeRow`, `registerWorkspace`) so the seeded shapes exactly match what the live query router (`createDbReadModelQueryPort` → the `sanitize*` re-gates) reads.
  - **The difference:** `provisionDevWorkspace` DERIVES from a real vault Markdown note (needs a vault + real files) and DELIBERATELY skips the global `dashboard_cards`. The demo-seed is **vault-FREE** (representative fixtures, zero setup) and **DOES** populate the Global aggregate the owner browses.
  - `READ_MODEL_KEYS` (worker `api/adapters/readModel.ts`): `dashboard`=dashboard_cards (Global Today, ws=null) · `recentChanges`=recent_changes · `ingestion`=ingestion_inbox · `projectDashboards`=project_dashboards · `workspace`/`project` cards · `registry`=workspace_registry · `global`=global_surface (GCL). The daily-brief retrieval (`createReadModelBriefingRetrieval`) assembles recentChanges + ingestion + an approval count.
  - Flag/env plumbing: the desktop main loads `.env` via the SOW_* allowlist (`main/dotenv-allowlist.ts`, desktop L15) and the forked worker child inherits `process.env` (worker L70 — a shell-export needs no desktop change). So the worker reads `SOW_DEMO_SEED` from `process.env` at boot; a `.env`-carried flag additionally needs `SOW_DEMO_SEED` in the desktop allowlist (small companion touch — see Q4).
  - **Safety posture (the lead was emphatic):** read-model-only (rebuildable), STRICT dev-gate (default OFF ⇒ byte-equivalent boot, no seed), never Markdown / never KnowledgeWriter / never a candidate-gate bypass / no egress / no secrets. This is a local DISPLAY fixture, not a semantic write — the one-writer posture (KW = sole Markdown writer) and the candidate-gate posture are structurally untouched.

## Acceptance criteria (what "done" means)
- [ ] A dev-only `seedDemoData(deps)` (new module, e.g. `composition/demoSeed.ts`) writes representative rows for the full Global Today via the read-model repo + a clock: the global `dashboard_cards` aggregate, per-workspace `workspace`/`project`/`project_dashboards` cards, `recent_changes`, `ingestion_inbox`, and the `workspace_registry` — for 2–3 representative demo workspaces (one per bucket: employer-work / personal-business / personal-life). Reuses provisionDev's shape-correct upsert helpers where they exist; adds the two keys provisionDev omits (`dashboard_cards` global + `ingestion_inbox`).
- [ ] Every seeded row passes the live read-side `sanitize*` re-gate (dashboard/recentChanges/ingestion/projectDashboards) — i.e. the seeded shapes are the REAL projection shapes, so `queries.*` return the rows and the renderer displays them. (Pin: a served query for each key returns the seeded rows.)
- [ ] STRICT dev-gate: `SOW_DEMO_SEED === "1"` (strict, not truthy) read at boot; default/absent ⇒ **byte-equivalent boot, zero seed writes** (factory-spy / no-put assertion on the OFF path). Idempotent: re-running the seed upserts (no duplicates), safe to run every boot.
- [ ] Read-model-ONLY: the seed calls ONLY `readModels.put`/`registerWorkspace` — it NEVER writes Markdown, never calls KnowledgeWriter/`applyPlan`, never routes a KnowledgeMutationPlan, never touches secrets or egress (pin: no KW/vault/secret dep in the module's surface; a grep/structural assertion).
- [ ] Never-throws / fail-safe at boot: a seed fault is a typed, redaction-safe error that does NOT crash boot (the dev fixture degrades, mirroring provisionDev's typed `DevProvisionError`).
- [ ] All unit tests pass (`apps/worker/test/composition/demoSeed.test.ts`) + an integration/reachability test (boot with `SOW_DEMO_SEED=1` → `queries.*` for each Today key return the seeded rows; OFF → all empty); `/preflight` clean.
