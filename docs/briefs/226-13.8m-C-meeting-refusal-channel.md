# /tdd brief — meeting_receipt_carries_a_code_only_refusal_channel

## Feature
Add the **code-only refusal channel** to the MEETING synthesis receipt (`MeetingRewriteReceipt`), so a poisoned-candidate run stops being byte-identical to a benign empty one on that path. **Knowledge-side producer only** — mirroring how 13.8m-A preceded its worker consumer.

## Mirror 13.8m-A exactly — the template is in-repo and its reasoning is in-code

`IngestRewriteReceipt.refusals` (`ingest-rewrite.ts:97`) is the shape to copy, and **three of its properties are load-bearing**:

1. **The field is REQUIRED, not optional** — `readonly refusals: readonly GroundedPathRefusal[]`. ⚠ **Do not carry over 13.8m-B's optionality**: that was the *worker seam* (`LivingVaultRewrite`), made optional to keep 13 existing containment fakes valid, and it is a **recorded bound** — *"a FUTURE adapter could omit it and the sink would silently never fire."* The knowledge **receipt** has no such compromise and must not acquire one. A required field makes omission **unrepresentable** rather than detected (contracts **L103**).
2. **The accumulator is HOISTED ABOVE the `try`** (`ingest-rewrite.ts:115`), with the in-code reason: *"a fault AFTER admission must not discard what was already refused, or a hostile run that hijacks paths and then trips a throwing port becomes byte-identical to a benign empty one — destroying exactly the distinction 13.8m-A exists to create."*
3. **It is present on the fail-safe `empty()` receipt** (`:116`), so the never-throws path still reports what it refused.

⛔ **Rule 7 — code-only, and the in-code comment on the source field says why:** reason codes only, **never paths or titles**. A refusal that carried the refused path *"would BECOME the exfiltration route it exists to report."* An empty array means *"nothing was refused"* — that is the distinction being created.

## RED test outline (Step 2)
1. **`benign_empty_run_and_refused_run_are_distinguishable`** — Asserts: two runs, one clean and one with a poisoned candidate, produce receipts that **differ** in `refusals` (empty vs non-empty). Why: the task's entire premise — KN-7's *rejected AND audited*. **The paired form matters**: a single "refusals is non-empty" assertion passes on a producer that always emits something.
2. **`refusal_carries_no_path_or_title_text`** — Asserts: given a hostile candidate whose path/title is a recognizable sentinel, no substring of it appears anywhere in the serialized refusals. Why: rule 7; the in-code reason on `ingest-rewrite.ts:93` — the report would become the exfiltration route.
3. **`fault_after_admission_still_reports_refusals`** — Asserts: a run that refuses a path and *then* trips a throwing port still returns the refusal. Why: `ingest-rewrite.ts:115`'s hoist. ⛔ **Mutation-verify**: un-hoist → RED → revert → report.
4. **`fail_safe_receipt_carries_refusals`** — Asserts: the never-throws/empty path includes accumulated refusals rather than a fresh empty array. Why: `ingest-rewrite.ts:116`.
5. **`refusals_is_required_on_the_receipt`** — Asserts (type-level, e.g. `@ts-expect-error` on a receipt literal omitting it): the field cannot be omitted. Why: L103 — omission unrepresentable, not detected; and it prevents 13.8m-B's recorded optionality bound propagating here. ⚠ If a `@ts-expect-error` goes **unused** (`TS2578`), that is the pin failing — same mechanism as worker L80's proven pin.
