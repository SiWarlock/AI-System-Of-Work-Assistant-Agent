# /tdd brief — startup_schema_compat_refusal_wiring

## Feature
Wire the already-built-and-tested `assertSchemaCompatible` predicate into the worker boot path so an incompatible app-version ↔ on-disk-schema-version pairing **refuses to boot** with a typed repair message (no silent forward-only break), before the worker serves. This is pure wiring + two small primitives (a read-schema-version engine method + a real app-version source) — the refusal predicate logic already exists.

## Acceptance criteria (what "done" means)
- [ ] `openDatabase` (`backends.ts:272`) reads the on-disk schema version and calls `assertSchemaCompatible(appVersion, onDiskVersion)` **before** `applyMigrations`; on `Err` it refuses to boot by throwing the typed `repair` message (fail-closed, no serving) in the same style as the existing `:287` migration-failure throw.
- [ ] A NEW read-schema-version method on each engine: SQLite reads `PRAGMA user_version`; Postgres reads `_sow_schema_version` (a `SELECT`). (Engines currently only *write* the marker via `recordApply`.)
- [ ] A NEW real app-version source constant (worker-side) fed to `assertSchemaCompatible` — aligned to the compat table's latest key (`0.2.0` / `CURRENT_SCHEMA_VERSION=2`), **NOT** `apps/worker/package.json`'s `0.0.0` (which would hit `unknown_app_version` and refuse to boot on every launch).
- [ ] **Genesis is not a refusal:** a fresh DB (`user_version = 0`, no `__drizzle_migrations` table) is treated as fresh → proceed to migrate to target, NOT `schema_below_minimum`. A test pins genesis-boots-clean.
- [ ] **A real incompatible pairing refuses:** on-disk schema **ahead** of the app (`schema_ahead_of_app`) ⇒ boot throws the typed repair; on-disk **below minimum** on a populated DB ⇒ refuse. Tests pin both.
- [ ] All unit tests pass (engine read-method + the `openDatabase` gate behavior); `/preflight` clean.

## RED test outline (Step 2)
1. **`sqlite_read_schema_version_returns_marker`** — after `recordApply(2)`, `readSchemaVersion()` returns 2; a fresh DB returns 0. Asserts: the read primitive. Why: §13 marker read.
2. **`pg_read_schema_version_returns_marker`** — same on the Postgres engine (`_sow_schema_version`). Asserts: dual-dialect. Why: §4/§13.
3. **`open_database_genesis_boots_clean`** — fresh DB (`user_version=0`, no migrations table) ⇒ no refusal, proceeds to migrate. Asserts: genesis ≠ refusal. Why: avoid a false `schema_below_minimum` (the live design point).
4. **`open_database_schema_ahead_refuses`** — on-disk version > app-supported ⇒ `openDatabase` throws the typed `schema_ahead_of_app` repair; never calls `applyMigrations`. Asserts: fail-closed refusal. Why: §4 "no silent forward-only break."
5. **`open_database_below_minimum_refuses`** — populated DB with a marker below min ⇒ refuse with the typed repair. Asserts: the other refusal reason. Why: §13.
6. **`open_database_compatible_pairing_proceeds`** — a compatible pairing passes the gate and reaches `applyMigrations`. Asserts: the happy path is unblocked. Why: don't break normal boot.

## Things to flag at Step 2.5
1. **Refuse-hard vs degraded-boot?** My default vote: **refuse-hard** — throw the typed repair (like the existing `backends.ts:287` throw). §4/§13 mandate "refuse to run" for a schema mismatch; degraded-serve is only the *separate* DB-unavailable fault mode (§4:159), not this.
2. **App-version source placement.** My default vote: a **worker-side constant aligned to `0.2.0`/`CURRENT_SCHEMA_VERSION=2`**, NOT `package.json 0.0.0`. Confirm whether it lives in `backends.ts` or a small shared `version.ts` (default: co-locate near the boot gate; a canonical version module can come later).
3. **Genesis detection.** My default vote: `user_version = 0` + absent `__drizzle_migrations` ⇒ fresh (migrate to target); only a populated DB with a real marker below min / above target refuses. Confirm the "populated" signal (presence of the migrations table).
