# /tdd brief — recent_changes_audit_projection_producer

## Feature
Wire a REAL recent-changes read-model producer: a pure worker composition port that queries workspace-scoped audit rows, projects them through the existing `projectRecentChanges`, and writes the `recent_changes` read-model row — so the desktop **Recent Changes** surface (and the "make the daily briefing real" arc) renders genuine ingest activity instead of the empty/dev-only fixture. This is the load-bearing "real data appears" first slice of Phase-9 producer wiring.

## Use case + traceability
- **Task ID:** 9.15 (Real read-model producers — recent-changes leg; promotes the Residual-9 "always-on producer wiring" / "Recent Changes R5: audit rows generated only inside Temporal flows" gap to a first-class task)
- **Architecture sections it implements:** `ARCHITECTURE.md §11` (Recent Changes surface, Flow 5) · `§10` (read-model query/serve layer — rebuildable derived state) · `§16` (never-throws typed Result) · `§5` (WS-8 isolation, safety rule 4) — workspace-scoped, no cross-workspace blend
- **Related context:** the READ PATH is already real (`queries.ts recentChanges` → `readModel.recentChanges(ws)` → `sanitizeRecentChanges`); the PROJECTOR is already real + unit-tested (`apps/worker/src/api/projections/recentChanges.ts` `projectRecentChanges`, WS-8 fail-closed, redact-by-type, opaque `deriveChangeId`). The ONLY gap is a production producer that reads audit rows → projects → `readModels.put`. Audit rows are already durably appended on every KnowledgeWriter commit (`knowledge_writer.commit`, carries `workspaceId`) + tombstone + disposition — so real scoped data exists the moment any ingest commits. The dev-only writer (`provisionDev.ts buildSyncRecentChange`, OFF by default) is what this replaces on the real path.

## Acceptance criteria (what "done" means)
- [ ] A pure producer — `refreshRecentChanges(input, deps)` (name TBD at Step 2.5) over injected `AuditRepository` + `ReadModelRepository` + `now` — queries audit **scoped to `input.workspaceId`** (`audit.query({ workspaceId }, limit)`), projects via `projectRecentChanges(records, workspaceId)`, and `readModels.put({ readModelKey: READ_MODEL_KEYS.recentChanges, workspaceId, data: { changes }, rebuiltAt: now() })`.
- [ ] **WS-8 (safety pin):** the produced row for workspace A contains ZERO records whose `AuditRecord.workspaceId !== A` (relies on BOTH the scoped `audit.query` AND `projectRecentChanges`' fail-closed drop of foreign/null-scope records); the read-model write key is the served `workspaceId`, never a record-derived value.
- [ ] Empty/no matching audit rows → writes a well-formed empty `{ changes: [] }` row (per the Step-2.5 empty-behavior decision), never throws.
- [ ] **Never-throws typed Result (§16):** an `audit.query` fault → typed `Err` (fail-closed, no partial/false write); a `readModels.put` fault → typed `Err`; a benign not-found is NOT a fault. No path throws.
- [ ] Ordering/cap: the projected changes round-trip cleanly through the read-side `sanitizeRecentChanges` re-gate (DESC-by-instant, cap 50) — the producer does not need to pre-sort/cap beyond what the projector already guarantees, but must not emit a shape the read-side rejects.
- [ ] **Reachable on the real path (Step 7.5):** the producer is invoked from the production trigger resolved at Step 2.5 — proven by an integration test that a real ingest commit (or the chosen trigger) results in a non-empty `recent_changes` row served by `queries.recentChanges`. (If the trigger is heavier than a bounded composition-root seam, wiring splits to slice 1b — flag at Step 7.5.)
- [ ] All unit tests in `apps/worker/test/api/projections/recentChangesProducer.test.ts` (or composition/) pass.
- [ ] `/preflight` clean.

## RED test outline (Step 2)
Tests in `apps/worker/test/api/projections/recentChangesProducer.test.ts`:

1. **`produces_recent_changes_from_scoped_audit_rows`** — Asserts: given N audit rows for ws A via the fake `audit.query`, `readModels.put` is called once with `{ readModelKey: recentChanges, workspaceId: A, data: { changes: <projected> }, rebuiltAt: <now> }`. Why: the core producer contract (`§11` Recent Changes read-model population).
2. **`ws8_foreign_record_never_lands` (SAFETY PIN)** — Asserts: an audit row carrying `workspaceId: B` (and a null-scope row) present in the query result never appears in the written ws-A row; the write key stays A. Why: safety rule 4 / WS-8 fail-closed (mirrors `recentChanges.test.ts` drop + L32 discipline).
3. **`empty_audit_writes_empty_row`** — Asserts: no matching rows → a `{ changes: [] }` put (or absent, per Step-2.5 decision), no throw. Why: rebuildable-empty read-model, §10.
4. **`audit_query_fault_fails_closed`** — Asserts: `audit.query` returns `Err` (or throws) → the producer returns a typed `Err` and does NOT call `readModels.put` (no partial/false write). Why: §16 never-throws-typed-Result, fail-closed.
5. **`readmodel_put_fault_propagates`** — Asserts: `readModels.put` `Err` → producer `Err`; no throw. Why: §16.
6. **`scoped_query_uses_served_workspace`** — Asserts: `audit.query` is called with `{ workspaceId: input.workspaceId }` (+ the bounded limit), never an unscoped query. Why: WS-8 scope at the read boundary.
7. **(integration)** `real_commit_surfaces_a_recent_change` — Asserts: over the wired path, a source ingest commit results in `queries.recentChanges(ws)` returning ≥1 change. Why: Step-7.5 reachability ("real data appears").

## Things to flag at Step 2.5
1. **Trigger mechanism (load-bearing).** How is the producer invoked so real data appears? (a) **post-commit refresh** at the worker source-ingestion seam (refresh the committing workspace after its audit row lands); (b) an **always-on Temporal schedule** rebuilding `recent_changes` per workspace on a cadence (LIFE-2); (c) **rebuild-on-read** (the `queries.recentChanges` procedure triggers a refresh). My default vote: **(a) post-commit refresh** — incremental, no schedule infra, reflects real activity immediately, stays in `apps/worker` territory; keep it bounded (a single scoped refresh, never a per-record loop) and fail-safe (a refresh fault surfaces a typed item, never blocks the commit). If (a) proves to touch the hot commit path invasively, fall back to (b) as a slice-1b follow-up.
2. **Empty-workspace behavior.** On no audit rows: write an explicit `{ changes: [] }` row, or leave the key absent (the read port already folds `not_found → empty ok`)? My default vote: **leave absent** — the read path already degrades not-found to empty, so writing an empty row is redundant I/O; only write when there is ≥1 change (revisit if a "last rebuilt at" freshness signal is wanted later).
3. **Audit query bound / recency window.** A fixed `limit` (e.g. most-recent 200 audit rows, projector caps to 50), or a time window? My default vote: **a fixed recent `limit`** (bounded, deterministic; the projector's cap-50 + read-side DESC-by-instant already govern what's shown) — a time window adds clock-dependence for no user-visible gain at this stage.
