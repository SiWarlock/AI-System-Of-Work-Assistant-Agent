## The finding, RE-DERIVED AT HEAD BY THE ORCHESTRATOR (do not take it on trust — but it does reproduce)

`stripMarkers` (`redaction-rules.ts:50-54`) replaces each marker literal with a **SPACE**, and `URL_USERINFO_CREDENTIAL` (`:69`) is `/\/\/[^/\s:@]+:[^/\s@]+@/` — **every character class excludes whitespace.** ⇒ **a marker inside a userinfo span breaks the span.**

**Measured at HEAD, four cases, run not reasoned:**

| input | raw `URL_USERINFO` | `looksUnsafe` | reading |
|---|---|---|---|
| `//u:p[REDACTED:raw]q@h` | `true` | ⛔ **`false`** | the entry's cleanest case |
| `//user:REALSECRET[REDACTED:raw]@host` | `true` | ⛔ **`false`** | ⛔⛔ **a REAL surviving secret, un-refused** |
| `//user:REALSECRET@host` | `true` | ✅ `true` | ⭐ **CONTROL — same span, no marker. The marker is provably the cause.** |
| `//user[REDACTED:credential]@host` | `true` | `false` | ⭐ **the trap: raw match is TRUE only because the marker supplies its own `:`** |

⭐ **The control row is the one the entry asserted and nobody had run.** ⛔ **Row 4 is why the obvious patch fails** — see below.

## ⛔ The obvious patch is a trap, and the measurement proves it

*"Also test the UNSTRIPPED string"* ⇒ **row 4 becomes a FALSE POSITIVE**: `//user[REDACTED:credential]@host` has no credential at all, and its raw `URL_USERINFO_CREDENTIAL` match is **entirely supplied by the marker literal's own colon**. ⇒ ***an already-redacted string would be re-flagged as unsafe, and on the `redact.ts:83` path that means `REDACTED_FIELD` — the whole field dropped.*** **That is an availability regression on a rule-7 surface, which is `### 24.123`'s failure mode in miniature.**
