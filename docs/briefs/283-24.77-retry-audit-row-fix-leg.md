## PART 2 — THE FIX

⛔⛔ **TWO SHAPES, AND CLOSING ONLY ONE IS A PARTIAL FIX WEARING A COMPLETION BADGE (`contracts L82`):**
> **(A)** fault at `audit.append` ⇒ the mutation ends with **NO truthful audit row anywhere** — only the false one.
> **(B)** fault at `revisions.record` ⇒ **a truthful row FOLLOWED BY a false one**, and the false one is
> **LATER** — a reader taking the most recent row sees *"0 changed."*

⭐⭐ **START FROM THE SELF-CONTRADICTION — it is a gift, because it detects the condition with NO KNOWLEDGE OF
RETRIES AT ALL:** the false row pairs **`0 file(s) changed`** with **`1 create(s)`**. `changes.length` is 0 while
the plan's create count is non-zero. **A validator can reject that pairing on the row alone** — no retry
awareness, no call-path assumption, no dependence on how the state arose.

⛔⛔ **THE CONSTRAINT, AND IT IS THE LOAD-BEARING HALF: THE GUARD MUST NOT REST ON THE GUARDS CLAIM 2 RESTS ON.**
Those are (i) the exactly-once approval CAS and (ii) `createCommitActivity`'s catch. ⛔ **`### 24.72`'s natural
remedy — *"let it throw so the fault is visible"* — REMOVES (ii).** ⇒ ***a fix that is only safe while those hold
is not a fix; it is a restatement of the coupling.*** **Assume both are gone and show the guard still holds.**

## RED test outline (Step 2)

1. **`retry_after_audit_append_fault_records_no_misdescribing_row`** — shape (A). Asserts: after a retry, no
   `AuditRecord` exists whose summaries describe a diff against a post-mutation base. **Preconditions asserted.**
