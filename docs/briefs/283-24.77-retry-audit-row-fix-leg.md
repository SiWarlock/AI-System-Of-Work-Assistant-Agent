## PART 2 — THE FIX

⛔⛔ **TWO SHAPES, AND CLOSING ONLY ONE IS A PARTIAL FIX WEARING A COMPLETION BADGE (`contracts L82`):**
> **(A)** fault at `audit.append` ⇒ the mutation ends with **NO truthful audit row anywhere** — only the false one.
> **(B)** fault at `revisions.record` ⇒ **a truthful row FOLLOWED BY a false one**, and the false one is
> **LATER** — a reader taking the most recent row sees *"0 changed."*

⭐⭐ **START FROM THE SELF-CONTRADICTION — it is a gift, because it detects the condition with NO KNOWLEDGE OF
RETRIES AT ALL:** the false row pairs **`0 file(s) changed`** with **`1 create(s)`**. `changes.length` is 0 while
the plan's create count is non-zero. **A validator can reject that pairing on the row alone** — no retry
awareness, no call-path assumption, no dependence on how the state arose.

⛔⛔ **THE CONSTRAINT, AND IT IS THE LOAD-BEARING HALF: THE GUARD MUST NOT REST ON THE GUARDS CLAIM 2 RESTS ON.**
Those are (i) the exactly-once approval CAS and (ii) `createCommitActivity`'s catch. ⛔ **`### 24.72`'s natural
remedy — *"let it throw so the fault is visible"* — REMOVES (ii).** ⇒ ***a fix that is only safe while those hold
is not a fix; it is a restatement of the coupling.*** **Assume both are gone and show the guard still holds.**

⭐⭐ **THE SUBSYSTEM ALREADY DECIDED THIS QUESTION ONCE, AND `applyPlan` NEVER GOT THE ANSWER.**
`packages/knowledge/src/knowledge-writer/tombstone.ts:254-265` — the OTHER KnowledgeWriter entry point —
**already guards an empty-change-set condition, deliberately, with a task citation.** ⇒ the fix **propagates an
existing posture rather than inventing one** (`L134`'s shape). That is why this is a defect and not a design gap.

⛔⛔ **AND THE PRECEDENT IS A TRAP — READ THIS BEFORE YOU COPY IT. THE SIBLING DOES *NOT* GUARD THE IDENTICAL
CONDITION, AND IT IS FALSE IN THE TWO RESPECTS THIS SLICE TURNS ON:**
> **(1) `tombstone.ts` tests `changes.length === 0` ALONE** — which is **exactly the widening this slice's
> discriminator forbids.** `24.77` requires **plan DECLARES mutations AND diff is empty**, so that a
> *legitimately* empty plan keeps its ordinary row. Copying the sibling's condition would reject honest no-ops.
> **(2) Its disposition is SUPPRESSION**, which `24.77` ruled against.
⇒ ⛔ ***A READER COMPLETING THE PARALLEL WOULD HAVE UNDONE THE SLICE.*** **The precedent is evidence that the
QUESTION was already settled — it is NOT a template for the ANSWER.**
⚠ **Why the sibling can afford suppression and you cannot:** it moves the signal into its return type
(`changed: false`) — a discriminator `WriteSuccess` does not have. **That gap is `### 24.80` and is deliberately
NOT folded into this slice.** Do not fix it here; if your design finds itself needing that discriminator, that is
a Step-2.5 flag, not a scope extension.
