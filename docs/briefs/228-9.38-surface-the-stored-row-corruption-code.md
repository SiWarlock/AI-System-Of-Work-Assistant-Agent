# /tdd brief — surface the stored-row corruption code to a diagnostic consumer

## Feature

Make a corrupt stored `Workspace` row **distinguishable** at a diagnostic surface, so an operator can see the corruption they have to repair — and close the long-open `#38` revoke-parse question with a pin rather than prose.

## Use case + traceability

- **Task ID:** 9.38
- **Architecture sections it implements:** `ARCHITECTURE.md §4` (Operational Storage — the read contract that produces the code) · `§16` (System Health, degrade-and-surface)
- **Related context:** task 9.36 (`be62e348`) + brief `223-9.36-workspace-read-regate.md` · session doc 134 · contracts **L106** (capability, not guarantee)

## Why this slice exists

The lead's Option-A refinement for 9.36 had **three** parts. Two landed: policy/egress consumers **fail closed** on a corrupt stored row, and the error is **distinguishable at the repository boundary** (`stored_row_schema_violation`, permanently non-retryable). **The third did not: no diagnostic consumer can report it.**

⇒ **A capability, not a guarantee** (L106): a correctly-typed, correctly-fail-closed error that reaches no consumer is indistinguishable from the failure it was created to be distinguishable *from*. **The operator cannot see the corruption they must repair.**

## Verified starting facts (orchestrator-established; contradict them if the code disagrees)

Positions are data as of `acb4b01f`, not the citation.

- **The gate exists and is wired both dialects.** `packages/db/src/adapters/workspace-read-gate.ts:46` mints `code: "stored_row_schema_violation"`; `packages/db/src/repositories/interfaces.ts:53` declares it *"permanent, non-retryable."* Both adapters call `parseStoredWorkspace(row)` in `get`.
- **⭐ The fold is total, and worse than the tracker described.** `apps/worker/src/boot.ts`'s `egressStatus` does `if (!isOk(got)) return { ok: true, value: failClosedEgress(wsId) };` — **no inspection of `got.error.code` at all** — and its `catch` folds a throw to the *same* value. Its own comment says *"Absence OR any store fault ⇒ the FAIL-CLOSED safe default."* ⇒ `stored_row_schema_violation`, `not_found`, and a plain outage are **byte-identical here**.
- **⚠ And it returns `ok: true` on failure**, so the *caller* cannot distinguish either — the information is destroyed at this frame, not merely unlogged. Any fix must therefore *add* a channel; there is no existing error path to widen.
- **`#38`'s answer, established:** `apps/worker/src/composition/egressRevoke.ts` performs **no parse of its own** — it never did, so nothing became redundant. Its read at `:53` (`deps.workspaceConfig.get(...)`) **does** flow through the gate (both dialect adapters gate `get`), and `:58-62` already classifies the new code. ⇒ **The answer to *"does the revoke still need its own parse?"* is NO — and the durable artifact is a pin that its read stays gated**, not a prose note. That is commit 2.

## Acceptance criteria (what "done" means)

- [ ] A corrupt stored row produces a **distinct, code-only** surfaced state an operator can act on, separate from absence and from a transient outage.
- [ ] **Empty/absent vs corrupt remain distinguishable** at that surface.
- [ ] **Every policy/egress consumer's fail-closed behaviour is unchanged, and pinned as such** by a test that would go RED if it were weakened.
- [ ] Code-only per safety rule 7 — **never** raw policy content, never a workspace's stored values, in the surfaced state or any log.
- [ ] A test pins that `egressRevoke`'s read flows through the gate, so a future refactor cannot silently bypass it (**commit 2**; closes `#38`).

## RED test outline (Step 2)

1. **`corrupt_row_is_distinguishable_from_absent`** — a `get()` returning `stored_row_schema_violation` produces a different surfaced state than one returning `not_found`.
   - Asserts: the two states are unequal, and the corrupt one carries the code.
   - Why: §16 degrade-and-surface; L106 — this is the whole point of the slice.
2. **`corrupt_row_is_distinguishable_from_outage`** — a thrown/transient failure is not reported as corruption.
   - Asserts: the throw path's state ≠ the corruption state.
   - Why: a false corruption report sends an operator to repair healthy data.
3. **`fail_closed_is_unchanged_on_corruption`** — raw egress still OFF, `zeroEgressOnly` still NOT-ESTABLISHED, on every failure branch.
   - Asserts: the posture fields are byte-identical to today's `failClosedEgress` on all three branches.
   - Why: ⛔ the hard constraint. **This test is the reason visibility cannot be traded for openness.**
4. **`surfaced_state_carries_no_policy_content`** — the state/log carries the code only.
   - Asserts: no workspace field values, no raw policy, appear in the surfaced payload.
   - Why: safety rule 7.
5. **`revoke_read_is_gated`** *(commit 2)* — `egressRevoke`'s read cannot bypass `parseStoredWorkspace`.
   - Asserts: given a corrupt stored row, the revoke path receives `stored_row_schema_violation` rather than an unvalidated object.
   - Why: closes `#38` with a pin. **Non-vacuity matters here** — prove it RED by having the fake return a row that would only pass unparsed.
