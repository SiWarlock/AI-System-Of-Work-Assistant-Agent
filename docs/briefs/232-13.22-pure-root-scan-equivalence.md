## ⭐ Why this is a slice and not a shrug — the recursion is the point

13.20 existed because `packages/contracts/CLAUDE.md` **claimed a boundary test that did not exist.** An unbacked claim of mechanical coverage.

**13.20's own residual is an unbacked claim of EQUIVALENCE between the two scanners it shipped.** Same defect class, one level in, **produced by the fix for the first instance.** Its reviewer caught it and deferred it deliberately — which is why this is a small slice now instead of a surprise in a month.

## Things to flag at Step 2.5

1. ⭐ **Byte-identity, or behavioural equivalence over a shared corpus?** **My default vote: byte-identity, fairly strongly.** Since all package-specific config arrives as arguments, **there is no legitimate reason for these files to differ at all** — so the apparent brittleness (a comment typo in one goes RED) **is the feature, not a cost.** Behavioural equivalence sounds stronger but needs both copies imported into one test, which reintroduces the cross-package coupling Q2 is about, for a tolerance nobody needs. ⚠ **Push back if** you find a reason they legitimately differ — that would invert this and is worth more than the slice.
2. **Where does the assertion live, and does it cross a boundary that matters?** Whichever suite hosts it will **read a file inside the other package.** **My default vote: `packages/domain`'s suite**, since domain already depends on contracts, so reaching that direction is natural and adds no new dependency edge. ⭐ **And the thing to state explicitly in the commit: reading a file path is NOT an import, so it does not trip the §2.5 invariant either copy enforces** — a future reader *will* wonder, and an unexplained cross-package `readFileSync` in a purity test is exactly the kind of thing someone "fixes." **Say why it's fine, in-code.**
3. **Is deduplication actually better, and is it available?** **My default vote: NO — pin, don't dedupe.** Sharing one copy needs either a test-only export from `packages/contracts` (polluting the public surface of the project's most sensitive package) or a helper outside both packages (a new shared location, and a build/tsconfig question in a repo where the `test/` tier already has its own DOM-less config). **Both are larger changes than the hole warrants, on the pure DAG root.** ⚠ Flag if you see a genuinely clean shared location I've missed — I'd rather one copy than two pinned copies, *if* it's free.
