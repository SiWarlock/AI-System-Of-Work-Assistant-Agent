## ⛔ THE COPY CONSTRAINT IS THE WHOLE SLICE
Four bans. Each has already been violated once in this codebase.

1. **`false` must not read as "cloud egress is possible."** That is L56 inverted — asserting a negative posture the field cannot support. Today it is the *likely* misreading, not a remote one.
2. **`false` must not read as local-only / safe.** The original defect.
3. ⛔ **No wording may imply "nothing leaves this machine," even when `true`.** The predicate covers **model-provider routes only** — connectors and Tool-Gateway external writes **never consult it**. So even a future `true` is a scoped claim, and unscoped copy would be a fresh false assurance with a *correct* value behind it.
4. **The claim must be DERIVED, never a constant** (forbidden-pattern #7). Test: change the governing state, and the rendered text moves.

**Scope of the bans:** the visible string **and** `aria-label` / `aria-labelledby` / `aria-describedby` / `title` / any injected CSS `content:`. L62 is explicit that a phrase ban on visible text alone let **20 of 25** restorations through, including the opposite-direction claim.

⚠ **A mechanical constraint that will bite you if you don't plan for it:** forbidden-pattern #7's grep bans the literal strings `local-only` and `zero-egress` in rendered `.tsx` under `apps/desktop/renderer`. So **"Zero-egress: not established" will trip `/preflight`.** Pick wording that describes the measured property without those two tokens — and treat that as a feature, since both tokens are exactly the shorthand that over-claims.
