## Root cause (verified by the orchestrator — confirm under /bug-hunt Step 1)
1. **The regression:** slice **9.12 (`80d387c6`, last round)** added `import { ok, err, isOk } from "@sow/contracts"` to `apps/desktop/main/open-in-vault.ts:17` — the **first *runtime* (non-type) `@sow/*` import in the Electron MAIN process**. (Preload has only type-only `@sow/*` imports — erased — so this is main-only.)
2. **Main externalizes `@sow/*`:** `apps/desktop/electron.vite.config.ts` uses `externalizeDepsPlugin()` for `main` (and `preload`), so `@sow/contracts` is NOT bundled — Electron main `require()`s it at runtime.
3. **The resolution split:** `packages/contracts/package.json` `exports` is condition-gated — `"sow-built" → ./dist/index.js`, `"default" → ./src/index.ts`. The **worker-host child** runs with `--conditions=sow-built` (per `worker-host.build.mjs`) so it gets `dist/`. **Electron main's Node runtime does NOT activate `sow-built`** → it resolves `@sow/contracts` via `default` → `./src/index.ts` → `require()` of raw TS → `SyntaxError: Unexpected token 'export'`.
   - `packages/contracts/dist/index.js` **is built** (turbo `build:sow` runs before `electron-vite dev`), so this is purely a **resolution/externalization** config issue — not a compile/build failure.

## Fix options (root-cause discipline — pick the one that fixes the TRUE cause, verify)
- **(A) PREFERRED — bundle the pure `@sow/*` into the main process:** exclude `@sow/contracts` from `externalizeDepsPlugin()` in the `main` build (`externalizeDepsPlugin({ exclude: ["@sow/contracts"] })`), so Vite/rollup resolves + transpiles + inlines it at build time (contracts is pure TS — zod/ajv, no native). This is the electron-vite-idiomatic fix for a TS-source workspace package. Keep `@sow/worker` + native modules externalized (main never imports `@sow/worker` directly — it spawns the worker-host child). ⚠ Verify the whole-barrel bundle tree-shakes cleanly (only `ok/err/isOk` are used); if the barrel drags heavy modules, narrow (deep import / targeted config) and re-verify. **No shared-surface touch → no coordination needed.**
- **(B) alternative — make Electron main resolve externalized `@sow/*` with the `sow-built` condition** (mirror the worker-host): activate `--conditions=sow-built` for the Electron main Node runtime. More design-consistent but brittle to wire cleanly through `electron-vite dev`; only pursue if (A) proves problematic.
- **(C) AVOID — change `@sow/contracts` package.json `default`→`dist`:** breaks the source-based vitest/tsc flows that rely on `default`→`src`; a shared-surface regression. Do not.

## Things to flag at Step 2.5 / during /bug-hunt
1. **Fix option — (A) bundle vs (B) runtime condition.** Default vote: **(A)** — targeted, electron-vite-idiomatic, no shared-surface touch, and the pure contracts barrel bundles cheaply. Confirm the build succeeds + no heavy-module drag after the exclude.
2. **Regression guard shape.** Default vote: a **build-artifact assertion** (no `.ts` require in `out/main`) — an Electron full-launch test is likely not CI-feasible; state the limitation rather than skipping a guard silently.
3. **Any OTHER runtime `@sow/*` import sneaking into main later?** Default vote: the exclude should cover the pure `@sow/*` set the main bundle imports at runtime (today: only `@sow/contracts`); document the invariant "main bundles pure `@sow/*`, externalizes only native/`@sow/worker` (spawned as a child)" so a future runtime import doesn't re-open this.
