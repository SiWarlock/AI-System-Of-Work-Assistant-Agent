# /tdd brief — calendar_renderer_surface

## Feature
The **Electron Calendar renderer surface** (task 9.9b, desktop track) — an unprivileged consumer of the just-shipped worker `query.calendar` read-model producer (#28, `8b4e3537`). A new dumb-render `Calendar` surface displays busy/free windows with GENERIC conflict explanations only, hydrated from `client.query.calendar.query()` through a re-validating `hydrateCalendar`, mounted via a routable AppShell nav entry (replacing the current DEAD non-routable Calendar `<div>`). Empty-until-wired is the normal state today (the producer serves empty until its adapter binds) → an HONEST empty state, never fabricated rows. This is the renderer half of the producer-first 9.9 split; it takes 9.9 to done and clears a `/phase-exit 9` blocker.

> **Territory: DESKTOP only.** Consumes the frozen `UiSafeSchedule` contract + the mounted worker query AS-IS. Do NOT touch `apps/worker/*`, `packages/contracts/*`, or any snapshot. `git add <path>` only; never `-A`.

## Acceptance criteria (what "done" means)
- [ ] **`Calendar` surface component** (`apps/desktop/renderer/surfaces/calendar/index.tsx`) — a pure dumb render of `readonly UiSafeScheduleEntry[]`: one card/row per entry (start/end window, busy indicator, generic `conflictExplanation` shown verbatim when present) + a DISTINCT honest empty-state (no entries → "No calendar connected", NO fabricated rows). NEVER imports electron/node/`@sow/worker`; reads ONLY the four allowlisted fields.
- [ ] **`hydrateCalendar(client, store)`** (`lib/live.ts`) — calls `client.query.calendar.query()` (no args), re-validates each entry via `UiSafeScheduleEntrySchema.safeParse` (defense-in-depth), drops malformed rows, best-effort try/catch: `ok`→populate; `{ok:false}`→empty non-crashing; thrown→caught empty. Wired into the cold-load `hydrate` path (NOT `hydrateScope` — calendar is global).
- [ ] **Store slice** `state.schedule: readonly UiSafeScheduleEntry[]` + `replaceSchedule` reducer (mirror `replaceIngestion`: replace, ref-stable no-op on empty→empty) in `store/projections.ts` + the store state type/initial state.

## RED test outline (Step 2)
1. **`calendar_renders_entries_and_empty_state`** — `<Calendar entries={[…]}/>` renders a card per entry (window + generic reason); `entries={[]}` renders the distinct "No calendar connected" empty-state, zero fabricated rows. Why: task 9.9 done-when.
