# /tdd brief — audit_drill_down_resolver

## Feature
Resolve `UiSafeRecentChange.changeId` (an opaque, one-way hash minted by the write-time
`recentChanges` projector) into leg A's `UiSafeAuditDrillSummary` — a new worker tRPC query
procedure that re-derives the backing `AuditRecord` server-side, re-checks workspace scope, and
returns ONLY `{event, occurredAt}`. `auditRef` never leaves the worker.

## Why the identity resolution works this way (read before Step 2)
`changeId` is **not reversible** — `deriveChangeId` (`apps/worker/src/api/projections/recentChanges.ts:62-65`)
is a one-way `sha256` over `[workspaceId, event, occurredAt, payloadHash, refs.join("")]`. There is no
`AuditRepository.get(id)` (`packages/db/src/repositories/interfaces.ts:561-565` exposes only `append` +
`query(filter, limit)` — confirmed, no row-id accessor exists). So resolution is: **re-fetch the
workspace-scoped candidate set, recompute the SAME hash per candidate, and find the match** — exactly
`resolveGlobalDrillDown`'s linear-scan-and-match shape, over a hash instead of a field-equality tuple.
⛔ **Reuse `deriveChangeId` — do not reimplement the hash.** It must be exported (currently
module-private) from `recentChanges.ts` and imported into `queries.ts`. Two independent implementations
of the same derivation is exactly what L39/L61 (contracts) name as the failure mode ("a predicate/derivation
lives once").

**The scan bound must be `RECENT_CHANGES_AUDIT_SCAN_BOUND`** (`apps/worker/src/composition/recentChangesProducer.ts:23`,
currently `1000`), not a new constant — and this is a "must agree," not a "happens to agree" (contracts L88's
distinction): any `changeId` a user could ever be drilling into necessarily passed through the SAME bounded
scan when `refreshRecentChanges` (`recentChangesProducer.ts:45-75`) built the feed that first showed it to
them. A different, smaller bound here could make a legitimately-displayed change fail to resolve; a larger
one buys nothing (nothing outside that scan window was ever rendered). ⚠ Inherits the SAME documented
arch_gap as recent-changes itself (`recentChangesProducer.ts:16-21`, FUTURE-TODO 2.9): `audit.query` orders
rowid-ASC (oldest-first), so a workspace whose lifetime audit rows exceed 1000 could have a `changeId`
that stops resolving. **State this in-code as a one-line cross-reference to the existing arch_gap** —
do not re-discover it as new.

## Acceptance criteria (what "done" means)
- [ ] `deriveChangeId` is exported from `recentChanges.ts` (no behavior change — export only) and imported
      into `queries.ts`; nothing else recomputes the hash independently.
- [ ] `ReadModelQueryPort` gains `auditEvents: (workspaceId: string) => MaybeAsyncResult<readonly AuditRecord[]>`
      (mirrors `copilotSurface`'s shape — a frozen-domain-record read, not yet UI-safe-projected).
- [ ] A new `resolveAuditDrillDown(readModel, input)` in `queries.ts`: fetches via `readModel.auditEvents(input.workspaceId)`,
      finds the record whose `deriveChangeId(r) === input.changeId` **AND** `r.workspaceId === input.workspaceId`
      (the second clause is the WS-8 defense-in-depth re-check ui-safe.ts:334 already promises — required even
      though the port call is nominally pre-scoped; see Step-2.5 test 3 below), projects to
      `{event: r.event, occurredAt: r.timestamps.occurredAt}`, and re-validates through
      `UiSafeAuditDrillSummarySchema.safeParse` before returning `ok`.
- [ ] No match (by hash, or by the WS-8 re-check failing) → typed `err`, never a throw, never a partial object.
- [ ] A hash match whose projected candidate fails `UiSafeAuditDrillSummarySchema` (e.g. an oversized/unsafe
      `event`) → typed `err`, never a thrown exception, never a wrongly-shaped `ok`.
- [ ] The returned `UiSafeAuditDrillSummary` carries **exactly** `{event, occurredAt}` — no `auditRef`/`actor`/
      `refs`/`payloadHash`/`workspaceId` reaches the response even when the source fixture populates them
      (structural key-set assertion, not just "the type says so" — TS erases at runtime, an object literal
      built wrong would still compile if it accidentally spread the source record).
- [ ] A new `auditDrill` query procedure is mounted on `buildQueryRouter`'s router, behind `authedResolver`
      (same auth gate as every other query procedure — no bespoke path).
- [ ] `createDbReadModelQueryPort` (`apps/worker/src/api/adapters/readModel.ts`) implements `auditEvents` for
      real, delegating to the injected `AuditRepository.query({workspaceId}, RECENT_CHANGES_AUDIT_SCAN_BOUND)`
      — **this is not optional**: `apps/worker/src/boot.ts:1626` assigns `createDbReadModelQueryPort(...)`'s
      return value directly to a `const readModel: ReadModelQueryPort`, so an incomplete real adapter fails
      `pnpm typecheck` at that exact line, not just in a test file.
- [ ] `DbReadModelQueryDeps` (`readModel.ts:403-406`) widens to include `audit: AuditRepository`; `boot.ts:1626-1629`
      threads `backends.repos.audit` (already available there — used at `boot.ts:1684`/`:1996` for other
      purposes) into the `createDbReadModelQueryPort({...})` call.
- [ ] Every existing `ReadModelQueryPort` object-literal fake gains a minimal `auditEvents` stub so the repo
      stays green (see "Files expected to touch" for the confirmed, scoped list — NOT a guess).
- [ ] `/preflight` clean (typecheck + tests — this project's `lint` is `tsc --noEmit`, no separate lint

## RED test outline (Step 2)
Tests to write in `apps/worker/test/api/procedures/queries.test.ts` (new `describe("buildQueryRouter —
auditDrill …")` block, mirroring the `globalDrillDown` block at `:794` for style):

1. **`audit_drill_resolves_a_real_changeid_to_its_narrow_summary`** — Asserts: given a fixture `AuditRecord`
   scoped to `KNOWN_WORKSPACE`, computing `deriveChangeId(record)` and calling `auditDrill({workspaceId,
   changeId})` returns `ok({event: record.event, occurredAt: record.timestamps.occurredAt})`. Why: the core
   contract, §10/§16.
2. **`audit_drill_unknown_changeid_is_a_typed_not_found`** — Asserts: a `changeId` matching no record in the
   scoped set → `err`, `cause.code` a drill-not-found variant, never a throw. Why: mirrors
   `globalDrillDown`'s `DRILL_TARGET_NOT_FOUND` precedent (`:865-875`).
3. **`audit_drill_never_returns_a_foreign_workspace_record_even_if_the_port_leaks_one`** — Asserts: a hostile
   fake `auditEvents` returning a record whose `workspaceId !== input.workspaceId` (planted alongside the
   correctly-scoped one) is REJECTED by the resolver's own re-check, not served. Why: WS-8 (rule 4); ui-safe.ts:334
   explicitly promises a re-check "on every drill," and this is the non-vacuous adversarial pin for it (mirrors
   L7's "pair every fail-closed negative with a hostile-input control" + L12/L32's re-check discipline).
4. **`audit_drill_never_leaks_dropped_fields`** — Asserts: `Object.keys(result.value).sort()` is **exactly**
   `["event", "occurredAt"]` even when the fixture `AuditRecord` populates `refs`, `payloadHash`, `actor`(if
   present on the model), and `workspaceId`. Why: leg A's explicit drop-list (`ui-safe.ts:345-355`), rule 7 —
   a type-only assertion doesn't survive to runtime, this does.
5. **`audit_drill_malformed_event_fails_closed_not_throws`** — Asserts: a fixture whose `event` violates
   `uiSafeToken`'s bound (oversized or unsafe-charset) still hash-matches (the hash is computed over the raw
   field), but `UiSafeAuditDrillSummarySchema.safeParse` rejects it and the resolver returns a typed `err` —
   never a thrown exception, never an `ok` with a malformed value. Why: mirrors `projectRecentChanges`'s
   own per-candidate fail-closed schema drop (`recentChanges.ts:90-92`), applied to the single-record path.
6. **`resolveAuditDrillDown_reuses_the_single_sourced_derivechangeid`** — Asserts (structural): `queries.ts`
   imports `deriveChangeId` from `../projections/recentChanges` rather than defining a second hash function
   (source-census pin, e.g. `grep -c "createHash" apps/worker/src/api/procedures/queries.ts` stays `0`). Why:
   L39/L61 — a derivation lives once.
7. **`createDbReadModelQueryPort_auditEvents_delegates_to_the_injected_audit_repository`** (in
   `apps/worker/test/api/adapters/readModel.test.ts`) — Asserts: calls `deps.audit.query({workspaceId},
   RECENT_CHANGES_AUDIT_SCAN_BOUND)` via a spy, forwards its `Result`, and folds a THROWN call to a typed err

## Things to flag at Step 2.5
1. **Touching `packages/evals/src/benchmarks/dashboard-warmload.bench.ts` (one `auditEvents` stub field) —
   evals is another track's territory.** This round's cross-area rule is "authorized per-slice, never
   generalised" (9.27's crossing, `IMPLEMENTATION_PLAN.md` Decisions-made). The touch here is a single
   additive stub property on an existing fake object literal (no logic, no behavior change to the benchmark),
   purely to keep the repo typechecking after `ReadModelQueryPort` widens. **My default vote: proceed, with the
   edit called out explicitly at Step 9 as a named cross-area touch** (comment in the diff naming why — mirrors
   this round's ruling that a disclosed cross-boundary edit is part of the edit, not something to hide) — the
   alternative (holding the whole slice for an eval-security sign-off on a one-line stub) is disproportionate,
   but I'm not deciding this unilaterally since it IS a real territory crossing. Escalate if you disagree.
2. **Error-code granularity — reuse `DRILL_TARGET_NOT_FOUND` (globalDrillDown's code) or mint a new,
   audit-specific one?** Reusing collapses two semantically different "nothing matched" cases (no global
   projection vs. no audit record) into one code, which an operator/log reader can't discriminate by code
   alone. My default vote: **mint distinct codes** — `AUDIT_DRILL_TARGET_NOT_FOUND` (no hash match, or the
   WS-8 re-check fails) and `AUDIT_DRILL_TARGET_UNSERVABLE` (hash matched, schema rejected) — precision costs
   nothing here and keeps the two drill paths' failure modes distinguishable in logs/health surfaces later.
3. **Procedure name — `auditDrill` or `auditDrillDown`?** `globalDrillDown` sets the naming precedent;
   `UiSafeRecentChange`'s own header (`ui-safe.ts:294`) calls this capability "a future worker-mediated audit
   drill." My default vote: **`auditDrill`** (shorter, and "Down" on `globalDrillDown` describes drilling
   DOWN INTO a workspace from a global view — this drill has no such directionality, it resolves an id within
   an already-known workspace). Low-stakes; take either.

## Lessons-logged candidates anticipated
- **Convention candidate** — "Resolving a projector-minted one-way opaque id server-side means re-fetching
  the same scoped candidate set the id was minted from and re-deriving the identical hash to find a match —
  never attempting to decode/reverse the id, and never maintaining a second reverse-lookup index that could
  drift from the mint site." (Generalizes `globalDrillDown`'s linear-scan-and-match shape to a hashed identity.)
- **Future TODO — operational** — the rowid-ASC/`RECENT_CHANGES_AUDIT_SCAN_BOUND` arch_gap (already tracked,
  2.9) now also bounds which `changeId`s are drillable, not only which appear in the recent-changes feed;
  worth a one-line cross-reference when 2.9 lands, not new work now.
