# /tdd brief — ingestion_inbox_park_sink_binding

## Feature
Bind the real read-model-backed ingestion-inbox producer at the composition root so a parked (no-match / below-threshold) source surfaces in the `ingestion_inbox` read-model — and is removed on triage disposition — instead of the dormant no-op stub. This is the always-on wiring of the 9.7-B producer core: the second Phase-9 "make the daily briefing real" producer leg (mirrors 9.15's recent-changes wiring).

## Acceptance criteria (what "done" means)
- [ ] `buildProofSpineActivities` binds the **real** `createIngestionInboxProjectionPort({ readModels: backends.repos.readModels, now: backends.now })` as the default `ingestionPark` (replacing the no-op stub at `buildActivities.ts:427`); `params.ingestionPark` remains an override seam (tests/fakes still inject).
- [ ] A parked source (no-match / below-threshold routing) upserts a row into `ingestion_inbox` for the source's OWN workspace — `queries.ingestionInbox` for that workspace returns the parked item (reachability: real park → non-empty row).
- [ ] On triage disposition, the parked `sourceId` is **removed** from the workspace's `ingestion_inbox` row (the item disappears from the inbox after resolution) — wired at the `triageRecordDisposition` seam (`buildActivities.ts:1065`), fail-SAFE (see AC below).
- [ ] **WS-8 (rule 4):** the write key is the source's / disposition's SERVER-BOUND workspace, never content-derived; a workspace disagreement fails closed (the producer core already enforces `source.workspaceId !== workspaceId ⇒ err`) — pin that a foreign-scoped park never lands in another workspace's inbox.
- [ ] **Fail-SAFE, never blocks the primary op (LESSON 76 / 21):** a `recordPark` / `recordDisposition` producer fault is swallowed at the wiring seam (best-effort, mirroring `recordParkBestEffort`) so it never fails the routing/park decision or the durable-disposition CAS record — the read-model is rebuildable-derived; a fault is surfaced typed (Future-TODO: a HealthItem), never thrown (§16).
- [ ] The disposition-remove runs only AFTER the durable `recordDisposition.record(...)` CAS succeeds (durable truth first; the inbox-remove is the derived projection).
- [ ] All unit tests in `apps/worker/test/composition/` pass; the reachability integration test (real park → non-empty inbox row; real disposition → item removed) passes.
- [ ] `/preflight` clean.
