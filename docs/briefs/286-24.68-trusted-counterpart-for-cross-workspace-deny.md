## ⛔⛔ THE LOAD-BEARING CONSTRAINT — WHY IT COULD NOT BE FIXED IN `#48`

**`24.45`'s remedy is REFERENTIAL.** It interpolates the candidate value **only after proving equality against a
TRUSTED COUNTERPART IN SCOPE** (`sourceWorkspace.id`).

⛔ **`denyDirectCrossWorkspaceRaw` receives only `req` (`CrossWorkspaceRawRequest`, `:270-275`), and
`fromWorkspaceId` AND `toWorkspaceId` are BOTH caller-supplied. There is NO counterpart to validate against.**

⇒ ⭐ **Reusing `24.45`'s sentinel without the validation that earns it is cargo-culting the spelling.** This is

**The mechanism diverges precisely where this task turns.**

**THE REAL FIX:** a signature/contract change so the caller passes the **registry-resolved** workspace(s) the
request is being evaluated against, letting the same referential check apply here.

## ⛔⛔ THE QUESTION THAT DECIDES WHETHER THIS SLICE IS REAL — ANSWER IT AT STEP 2.5 BEFORE IMPLEMENTING

**Can the trusted counterpart actually be SUPPLIED today?**

`denyDirectCrossWorkspaceRaw` is **not production-reachable** — `authorizeCrossWorkspaceRawRead` has no caller
and `CrossWorkspaceLinkMap` is never constructed outside tests (verified at `#48`'s Step 2.5).

⇒ ⛔ **If the only thing that will ever fill the new parameter is a test fixture, then the "trusted" counterpart
is trusted BY CONVENTION, NOT BY CONSTRUCTION — and you will have re-created the exact defect one layer up,
with a stronger-sounding name.** That is `L147` (trusted provenance is not validated shape) arriving through the
remedy, and `L123` (an optional/unfilled guard is type-indistinguishable from a bound one at the call site).

**Establish and report, before writing the fix:**
1. **Who would supply the counterpart in production** — name the call path, or state that none exists.
2. **Whether the value they'd supply is registry-resolved** (an authority vouched for it) **or merely
   caller-echoed** (someone passed it). ⚠ *"Registry-validated" means "someone inserted it"* — `### 24.83`'s
   falsified justification, and the same trap lives here.
3. **If no production supplier exists:** say so plainly. The honest outcome may be *a contract shaped so the
   value CANNOT be caller-echoed* (`L103`: make the violation unrepresentable) rather than a parameter added now
   and filled correctly later by someone who does not know why it exists.

⭐ **Reachability governs DISPOSITION, never ROUTING or whether this is real** — standing rule. **It is not a
reason to skip the slice; it IS a reason the design question above outranks the implementation.**
