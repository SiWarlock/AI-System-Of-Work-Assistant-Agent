## Decisions made

- **13.23 — sparse `Partial<Record<...>>`, not exhaustive, and not a single merged count.** Exhaustive-by-construction was the orchestrator's stated preference, reversed after establishing `GroundedPathRefusal` (composed into `WithheldReason`) exports no member list — an exhaustive map would force re-declaring it, which criterion 3 (composed, never re-declared) forbids. A single count was ruled out from the start: `ws_scope_mismatch` (the WS-8 signal) must stay individually distinguishable, and a merged number destroys exactly the distinction the field exists to create — the same argument `entityRefsRejected`'s own doc comment already makes.
- **13.23 — the ADD's trigger code corrected mid-build.** The orchestrator's ADD asked for a pin using `ws_scope_mismatch` to prove the meeting path's direct call site doesn't flow through the new channel. Read from source before building it: `rewriteVaultForMeeting` gates `deps.gbrain.workspaceId===input.workspaceId` ONCE, before its per-ref loop even starts — a mismatched port short-circuits to an empty receipt and never reaches `resolveEntity`, so `ws_scope_mismatch` is structurally unreachable on that specific path (double-gated: this outer check plus `resolveEntity`'s own). Used `ambiguous` instead (reachable there, also not a `GroundedPathRefusal` member, demonstrates the identical gap). This also **corrected the orchestrator's own ruling**, not just the test choice: leg C had been recorded as a Done-when blocker on the grounds that the meeting path drops `ws_scope_mismatch` specifically — it structurally cannot, so legs A+B alone satisfy 13.23's Done-when and leg C dropped to a completeness item, not a blocker. The orchestrator verified this independently before accepting it (contracts L116) and rewrote the tracker.
- **13.23 — security review found a latent L65-shaped gap, fixed in-slice.** The withheld-reason accumulator, originally a plain object indexed by `res.reason`, was safe for every *current* `WithheldReason` member (verified none collides with `Object.prototype`) but had no structural guarantee against a *future* `GroundedPathRefusal` member named `toString`/`constructor`/`__proto__` — the exact shape `ENTITY_NAMESPACES` two lines away in `entity-resolver.ts` already guards against with a `Map`. Fixed by accumulating in a `Map` and converting to the public plain-object shape once via `Object.fromEntries` (which uses `[[DefineOwnProperty]]`, not assignment — safe even for a hypothetical `"__proto__"` key). Banked by the orchestrator as **contracts L128**.
- **24.12 — Option A (structural enforcement) over Option B (a detector), and why.** The brief left this open with a stated lean toward A; confirmed by reading `ingest-rewrite.ts`'s `mergeStructural` (structural parity mutations legitimately ride inside any workspace's plan, so the legitimate-unprefixed case doesn't force A to degrade) and by the L106 ledger's own weight — a detector needs a host, and building one would risk becoming a sixth produced-and-dropped instance. A also "wires itself": it's the writer's own live production path, so no `apps/worker`/`apps/desktop` change was needed for the DEFAULT to be safe.
- **24.12 — the legacy-workspace id and the `sources/` subtree are hardcoded DATA duplications, not imports, by design.** `packages/knowledge` cannot import `packages/policy` (the brief's own layering constraint) or `apps/worker` (the reverse of this module's own layering direction). Both constants (`LEGACY_UNPREFIXED_WORKSPACE_ID`, `SOURCE_NOTE_SUBTREE`) duplicate a VALUE owned elsewhere, documented in-code with the paired site, the drift direction (both fail closed and loud, never silently), and — for the legacy-workspace one — an owed composition-root single-sourcing follow-up.
- **24.12 — both Step-8 reviewer findings were real, verified independently, and fixed in-slice; neither was taken on the reviewer's word alone.** [Critical, security] `isStructuralSurface`, reused standalone outside `admitGroundedPath`'s own call order, let `"Logs/../employer-work-secret.md"` string-match the structural exemption while `path.resolve()` landed it at the vault root — reproduced directly via a `node -e` script before touching any code. Worse on inspection: the SAME shape defeated the plain workspace-prefix match too (`"employer-work/../secret.md"`). Fixed by gating the ENTIRE predicate behind `hasNoTraversalSegments`, extracted from (not re-derived from) `admitGroundedPath`'s own check. [High, code-quality] `sources/<workspaceId>/<digest>.md`, the documented convention `apps/worker/src/composition/sourceNotePath.ts` derives for every real ingested source, was rejected by the first-segment-only rule for every workspace but personal-business — reviewer-verified via `git stash` + real `apps/worker` test runs (40/40→34/40); reproduced independently before fixing. Recognized as a second sanctioned prefix shape.
- **24.12 — the cross-territory item (worker test regression #6 of 6) split under contracts L121, ruled by the orchestrator.** Root-caused (not just observed) to `packages/workflows/src/activities/commitKnowledge.ts`'s `mapWriteFailure`, whose `default:` case silently absorbs the new `workspace_path_violation` code into a generic `commit_failed` — the guard IS working correctly; the test's own fixture (an unprefixed path for a non-legacy workspace) is now genuinely caught by it, one step before the secret-scan it intends to test. Two halves: (b) the test fixture — assertion-preserving, "my change broke this and it cannot land red" — taken myself, its own pathspec-limited commit in `apps/worker`. (a) `KnowledgeCommitFailureCode` (a closed union in worker's port) needing a 6th member — a design change to another track's territory, routed by the orchestrator as task **24.23**, not built here. The orchestrator additionally banked the generalization (a `default:` branch over a closed union is a silent absorber for every future member, contrasted with the sibling `assertNever`-guarded `defaultSeverityForFailureClass`) as **contracts L134**.
- **24.12 — the residual is worded exactly as the orchestrator specified, because the compressed version is false.** Until task 24.23 lands: a `workspace_path_violation` flattens to `commit_failed` at the `packages/workflows` boundary. **The write is still rejected — fail-closed holds — only the reason is lost.
